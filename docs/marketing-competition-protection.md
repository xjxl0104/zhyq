# 全民营销：推荐入口与竞争保护白名单

本次基于 `test` 分支修改。小程序使用 uni-app Vue 3；伙伴业务走 `/mp/v1`，云仓业务走 `/wh/v1`，后端 Spring Boot + MyBatis-Plus + MySQL + Flyway。

## 推荐入口

客户页原来通过模板事件调用导入的导航函数。源码中已有绑定，仅凭截图不能确认线上无响应的具体原因，也无法确认线上包是否与当前分支一致。本次改为微信原生 navigator 跳转，且在空列表、读取失败、加载中都保留入口。构建检查会验证产物中存在正确的 navigator 和页面路径。通用导航函数增加失败提示，推荐提交也捕获失败。

仍需使用微信开发者工具导入 `miniapp/dist/build/mp-weixin` 并真机验证：有客户、无客户、接口失败时均可点击推荐新客户，进入表单并返回客户页。

## 产品规则

- 云仓工作台、加盟申请页均有入口。不要求客户关系证明或任何联系人、电话、订单数据。
- 每条仅录入一个品牌或公司名称，1–100 字，每仓最多 500 条；可查看、添加和确认移除。品牌别名、公司全称分别添加。
- 同一运营主体内，名称保存后用于后续报备的公司名称及可选品牌名称校验，命中即阻止创建预锁。客户插入和预锁处于同一事务，拦截会回滚新增客户。
- 规范化 Unicode 全半角、空格、英文大小写后精确匹配，不使用包含匹配或自动推测品牌归属。未填品牌且公司名称不同，无法根据品牌推断命中。
- 名单不作为客户归属或成交证明；不追溯撤销已有报备或合同，不提供独占名称声明。不同云仓可分别保护同一名称。
- 退出云仓不能新增保护；已有保护保留，需由本仓明确移除。不设置自动过期以免无提示解除保护。

## 保密边界

- 云仓身份来自 JWT，不接受请求里的 warehouseId；读取和删除同时限定云仓及 tenantId。没有伙伴端查询、跨仓检索或管理端明文导出接口。
- 名称使用现有 FieldEncryptionService 的 AES-GCM 加密；检索使用带用途前缀的 HMAC-SHA256，不存储明文名称或可直接字典比对的普通摘要。
- 审计只保存动作与记录 ID，不保存名称或密文快照。名单不进入普通云仓资料响应。
- 页面不注册分享回调，并隐藏分享菜单；离开页面清空名称与名单，拒绝迟到读取回包。不写本地存储。
- 加密保护针对数据库内容和应用访问；拥有解密密钥的服务器运维仍属于信任边界。无法阻止合法账号手动截图。
- 报备拒绝只给出通用核验提示，不透露保护仓或名单。但拦截反馈本身并不能完全消除在线猜测风险，后续可按运营需求增加异常报备监测。

## 部署与验证

1. 后端发布时执行 Flyway V86，新增保护表和客户 brand_name 字段。应先部署后端，再发布小程序。
2. 复用 `ZHYQ_FIELD_ENCRYPTION_KEY`，值为 Base64 编码的 32 字节密钥。缺失配置时拒绝新增名单；已有名单时校验失败关闭。不要直接替换生产密钥；轮换需重加密名称并重建 HMAC 索引。
3. 微信构建：`pnpm run build:mp-weixin`。额外核验保密名单没有原生分享回调。
4. 前端新增测试覆盖保存失败保留输入、仅提交名称、关闭页面清空并拒绝迟到回包、确认移除。
5. 后端新增测试覆盖规范化、密文写入、通用命中提示、按所有者删除及缺失密钥拒绝写入。运行 `mvn test -Dtest=MktCompetitionProtectionServiceTest,MktOnboardingAndLockServiceTest,MktTransitionGuardTest`。

2026-10-12 已在 `D:\本地运行环境配置` 安装 Java 17、Maven、Node.js、pnpm、MySQL 8。相关 58 项后端测试全部通过，后端打包及微信构建通过。本地 MySQL 从空库执行 85 个迁移成功，到达 V86；真实接口通过跨仓隔离、越权移除拒绝、伙伴读取拒绝、名称去重、命中拦截及移除后正常推荐等 6 项验收。

前端现有及新增测试共 171 项，163 通过、8 失败；在未修改的 HEAD 导出副本中复现相同 8 项失败，涉及 H5 条件编译的下载与登录测试。线上发布前仍需按部署顺序执行迁移，并完成微信真机联调；本地验收没有操作线上数据。
