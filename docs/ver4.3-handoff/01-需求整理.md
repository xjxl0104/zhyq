# 需求整理

## 一、版本与交付要求

- 在 ver4.2 基础上继续开发，新版本命名为 `ver4.3`。
- 按已经确认的方案连续实现、验证，并推送到 GitHub 仓库 `xjxl0104/zhyq` 的 `ver4.3` 分支。
- 不改动已经上线的两个超级管理员及现有业务数据。
- 不把用户工作簿、账号明文、密码、Cookie、令牌或其他敏感资料提交到仓库。

## 二、物业租金及物业管理费

用户提供《物业租金及物业管理费基础资料》工作簿，并明确要求：

- 现有系统按照表格内容调整，一切以表格内容为准。
- 系统承接表格 27 列，包括协议、租户、空间、面积、合同期限、递增、免租、优惠/抵扣、租金、物业费、保证金、收款时间、收款账户和备注。
- 导入前预览并核对总计，不能直接把未确认的数据写入正式业务表。
- 导入行必须绑定系统中的租户、合同以及空间或房间。
- 租金、物业费、租金保证金和物业保证金分别生成财务账单。
- 收款账号属于敏感数据，列表和导出只显示掩码，完整值加密保存并单独授权查看。
- 重复导入不能生成重复账单；修订版工作簿不能复制出第二套应收登记。
- 已确认导入需要保留审计批次，并在没有下游账单或实收数据时支持受控撤销。

## 三、自动售货机 SaaS 整合

目标厂商入口为 `https://fanmaiji.top/index?isFrom=login`。用户确认厂商目前没有可用开放 API，因此采用以下边界：

- 在智慧园区中增加自动售货机应用入口和本地经营工作台。
- 只以 HTTPS 新窗口打开厂商页面，不自动登录，不抓取页面，不保存或转发厂商密码、Cookie、验证码或智慧园区令牌。
- 在没有真实厂商 API/导出格式前，采用智慧园区标准模板进行受控数据导入。
- 支持机器、销售、补货、故障、对账五类数据。
- 每类数据均需精确表头、逐行预览、错误行排除说明、文件防重、业务键更新、确认入库、批次历史和受控撤销。
- 售货机销售额进入数据中心“经营收入来源”，但不伪装成租金或物业账单。

## 四、权限要求

- 超级管理员沿用 ver4.2 的用户、角色和权限配置能力。
- 应收模块按查询、新增、编辑、导入、确认、生成账单、导出、删除、查看完整账户拆分权限。
- 售货机模块按本地数据查询、导入、打开厂商系统、配置状态拆分权限。
- 页面只能显示当前账号有权执行的操作；缺少某一项权限时，其他有权功能仍应正常使用。

## 五、明确不做

- 不执行 Excel 宏、外部链接或服务器端公式计算，只读取已有缓存值并保留非敏感公式审计。
- 不保存物业源工作簿明文副本。
- 不在没有证据的情况下宣称售货机厂商已开放 API。
- 不绕过厂商登录、验证码或其他安全控制。
- 不直接删除或篡改 Flyway 历史记录，不用手工改数据库代替受控导入和回滚。
