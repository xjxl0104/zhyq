# ver6.7–ver6.8 动效界面升级设计

日期：2026-08-28  
基线：`a5b419827605efcc76fcc46fc4d87f3444aeb5b0`（远端 `ver6.6`）  
目标分支：`ver6.7` → `ver6.8`

## 1. 目标与范围

本次升级拆成两个连续版本：

- `ver6.7`：在远端 `ver6.6` 基线上重做已确认的布局精简，并为左侧多级导航加入适合后台系统的 Gooey 选中动效。
- `ver6.8`：继承 `ver6.7`，建立可复用的毛玻璃表面，将其应用于全部上传区域以及少量展示型卡片。

两个版本都保持业务接口、路由结构、权限、上传鉴权、文件校验和数据提交逻辑不变。当前本地 `ver6.6` 工作树中的未提交改动不作为代码基线，也不被修改或带入新分支。

## 2. 非目标

- 不把 ReactBits 的 React 组件直接引入 Vue 项目。
- 不引入 React、Tailwind、GSAP 或新的运行时动效依赖。
- 不重写 Element Plus 的菜单、上传组件或对话框。
- 不改变父级菜单的展开/折叠语义。
- 不将毛玻璃全局应用到表格、查询表单、业务弹窗或高密度数据卡片。
- 不创建或修改后端接口、数据库迁移和权限规则。
- 不在未经用户要求的情况下推送分支、创建标签或发布部署。

## 3. 版本与分支拓扑

```text
a5b4198 (远端 ver6.6)
   └── ver6.7
         ├── 既有布局精简
         ├── Vue Gooey 左侧导航
         └── ver6.7 验收与发布说明
               └── ver6.8
```

`ver6.7` 使用独立工作树，从精确 SHA `a5b4198` 建立；`ver6.8` 只在 `ver6.7` 完成、测试和提交后建立，确保两个版本可分别审阅和回退。

## 4. ver6.7：布局精简

### 4.1 已确认改动

- 删除 `TagsView` 渲染、组件文件和仅供标签页使用的 Pinia store。
- 项目切换器从顶栏左侧移到右侧操作区，并位于“监控大屏”按钮之前。
- 删除 AI 助手占位入口、提示逻辑和对应样式。
- 删除暗色切换入口、暗色 CSS、Element Plus 暗色变量包和主题切换 store。
- 启动时清理旧版本遗留的 `zhyq_dark` 本地设置与根节点 `.dark` 类，固定使用亮色。
- ECharts 公共封装改用确定的亮色调色板，不再订阅主题状态。
- 切换项目时仍销毁并重建当前 `keep-alive` 内容，保证项目数据刷新。

### 4.2 兼容性

删除标签页后，路由、侧栏菜单和浏览器前进/后退仍是页面导航的唯一来源。删除暗色功能不影响独立的监控大屏视觉；监控大屏可继续保留其业务场景要求的深色指挥中心样式，因为它不属于可切换的后台主题。

## 5. ver6.7：Gooey 左侧导航

### 5.1 方案选择

采用“Vue 原生覆盖层”方案：保留现有 `el-menu`、递归 `MenuItem.vue`、路由和键盘语义，在菜单外包裹一个专用 Gooey 容器。容器只观察当前激活的叶子菜单并在其下方绘制液态指示器与短暂粒子。

不采用以下方案：

- 完全重写菜单：会重复实现多级展开、键盘导航、路由选中和折叠兼容，回归面过大。
- 纯 CSS 伪元素：实现简单但无法可靠跟踪多层叶子、滚动位置和程序化路由变化，也难以清理粒子生命周期。

### 5.2 组件边界

新增 `frontend/src/layout/GooeyNav.vue`：

- 接收 `activePath`，内部渲染默认插槽，插槽中放现有 `el-menu`。
- 根节点作为定位坐标系，液态指示器和粒子层使用 `aria-hidden="true"`，不进入可访问性树。
- 通过根节点查找 `.el-menu-item.is-active`，不依赖菜单数组的层级深度。
- 在首次渲染、`activePath` 变化、菜单展开完成、滚动和容器尺寸变化后重新测量选中项。
- 测量失败时隐藏效果层，不阻塞菜单点击或导航。
- 组件卸载时断开 `ResizeObserver`、移除监听器并清理所有定时器。

`Layout.vue` 只负责传入 `activePath` 并保留现有菜单数据流；`MenuItem.vue` 不承担动效状态。

### 5.3 动效行为

- 激活背景是一个跟随叶子菜单位置移动的圆角液态胶囊。
- 胶囊使用现有品牌靛蓝为主色，辅以淡紫和少量暖橙粒子，保证与后台系统的亮色设计一致。
- 粒子数量上限为 8，扩散距离限制在侧栏可视范围内，单次生命周期不超过 900ms。
- 初次进入页面只显示静态胶囊；后续路由变化才触发一次粒子爆发。
- 父级菜单标题只负责展开/折叠，不显示“已选中”液态胶囊，避免把分组误认为当前页面。
- 激活文字和图标保持真实 DOM，由 CSS 提升到效果层上方；不复制可见文本。
- 程序化路由、浏览器前进/后退与键盘激活得到同样的选中位置反馈。

### 5.4 减少动画与降级

当 `prefers-reduced-motion: reduce` 生效时：

- 禁止粒子和胶囊弹性移动。
- 保留无动画的品牌色选中背景和清晰焦点环。

不支持 `ResizeObserver` 或滤镜的环境退化为现有静态选中样式。动效层设置 `pointer-events: none`，不会截获点击、滚动或键盘输入。

### 5.5 测试

- 布局测试：确认项目切换器位于右侧、TagsView/AI/暗色入口不存在。
- 亮色初始化测试：确认旧暗色偏好和 `.dark` 类被清理。
- Gooey 组件测试：确认初始定位、路由变化后的指示器更新、粒子上限、粒子清理和组件卸载清理。
- 减少动画测试：确认该媒体偏好下不生成粒子。
- 集成测试：确认多级菜单展开、叶子导航、外部监控大屏入口和项目切换行为保持不变。

## 6. ver6.8：毛玻璃表面系统

### 6.1 视觉方向

参考用户提供的 Uiverse 毛玻璃卡片，但重新适配当前亮色企业后台：

- 主体使用半透明白色表面、细白边框和轻量阴影，不使用原示例的大面积黑底。
- 背景光团使用品牌紫到暖橙的低饱和渐变，并以 16–20 秒的低速旋转提供环境动势。
- 文字、图标和上传状态保持 Element Plus 的语义色与对比度。
- 实现使用普通 Vue 与 scoped/global CSS，不复制 Tailwind 类，也不引入 Tailwind。

### 6.2 基础组件

新增 `frontend/src/components/GlassSurface.vue`：

- `variant="upload" | "card"` 控制上传区和展示卡片的密度、圆角与内边距。
- 背景光团和装饰层标记为 `aria-hidden="true"`。
- 默认插槽承载真实交互内容，视觉层全部位于内容下方并禁用指针事件。
- 通过 CSS 自定义属性接入现有 `--brand`、圆角、边框和阴影变量。
- `@supports` 为不支持 `backdrop-filter` 的浏览器提供不透明浅色背景。
- `prefers-reduced-motion` 下停止光团旋转。

不在该组件中放上传请求、文件状态、按钮或业务文案，确保它只负责视觉表面。

### 6.3 上传区域覆盖

以下 `a5b4198` 中已有上传入口全部使用 `GlassSurface variant="upload"`，原有上传组件和事件保持不变：

1. `frontend/src/components/FileUpload.vue`：通用业务附件。
2. `frontend/src/views/app/components/VendingImportDialog.vue`：售货机 Excel 导入。
3. `frontend/src/views/finance/components/ReceivableImportDialog.vue`：应收明细 Excel 导入。
4. `frontend/src/views/property/ResponsibleUnit.vue`：责任单位导入。
5. `frontend/src/views/suggestion/FeedbackFab.vue`：建议截图。
6. `frontend/src/views/suggestion/MySuggestions.vue`：截图和普通附件。

上传视觉状态必须覆盖：空态、拖拽悬停、文件已选择、上传中、成功、失败、达到数量限制和禁用。`el-upload` 的输入、拖拽、文件列表、删除和预览仍是真实可交互元素。

### 6.4 展示型卡片覆盖

毛玻璃卡片只进入以下低密度展示区域：

- `frontend/src/views/dashboard/Index.vue` 的顶部指标卡和经营概览展示卡。
- `frontend/src/views/app/AppCenter.vue` 的收藏卡和应用卡。

以下区域明确不应用：

- `.table-card`、数据表格和分页容器。
- `.search-bar` 查询表单。
- 业务编辑弹窗、审批表单和设置页。
- 财务、工单、设备等信息密集的全站统计卡。

这样既能建立可识别的视觉亮点，又不会让几十个页面持续运行旋转光团或降低数据可读性。

### 6.5 性能与可访问性

- 动画只改变 `transform`，不动画化宽高、边距或模糊半径。
- 每个毛玻璃表面最多一个光团；隐藏的对话框不应保持可见动画。
- 文字对比度以实际背景最亮和最暗位置检查，正文目标至少 4.5:1。
- 保留上传区的键盘焦点、可访问名称、拖拽提示和错误恢复文案。
- 毛玻璃效果不可成为理解上传状态的唯一信号。

### 6.6 测试

- `GlassSurface` 测试：验证视觉层不拦截交互、variant 类、插槽渲染和装饰层无障碍属性。
- 上传集成测试：验证包装前后的文件选择、限制、解析预览、删除和提交事件保持一致。
- 状态视觉检查：空态、拖拽、已选择、上传中、成功、失败和禁用。
- 展示卡检查：工作台和应用中心在长中文、窄屏与默认数据下不溢出。

## 7. 数据流与错误处理

两个版本都不新增业务数据流：

```text
用户输入 / 路由变化
        │
        ├── Element Plus 菜单与 Vue Router（原逻辑）
        │       └── GooeyNav 只读取选中项几何信息
        │
        └── Element Plus Upload（原逻辑）
                ├── 原校验 / 鉴权 / API / 错误处理
                └── GlassSurface 只提供视觉容器
```

Gooey 测量或动画异常时隐藏效果并继续导航；毛玻璃滤镜不支持时使用纯色回退。视觉增强不得吞掉异常、改变上传结果或阻止用户继续操作。
