# 财务总览 · 合同收款全景（设计）

日期：2026-10-14 · 状态：已实施（第一步）；历史收款导入待设计

## 目标

用户反馈：财务总览“字太多、图表太少”；后续会上传大量过往合同，需要一眼看出**每份合同应收多少、已收多少、还欠多少、欠的是哪几笔款**，让新同事看一眼就懂。

成功标准：

- 首屏以图表与数字为主，大段说明文字移除或收进提示。
- 按合同展示收款状态，可展开到费用类型（租金、物业费、保证金、水电费……），并可跳到该合同的账单明细。
- 已录入但尚未生成账单的合同（如刚上传的历史合同草稿）以“未出账”单独显示，不混入“未付款”。
- 面板只读，不改变计费、收款、合同状态任何规则。

## 现状依据（2026-10-14 生产库只读统计）

- 14 份合同、116 张应收账单、30 笔收款。
- 账单 100% 可追溯到合同：110 张 `fin_bill.contract_id` 直接关联；其余经 `fin_receivable_register.contract_id` 关联。
- 合同导入（Excel/CSV/PDF）只生成合同草稿；应收明细登记表导入生成登记与账单；**历史已收款没有导入入口**（列为第二步）。

## 口径

- 账单范围与现有总览一致：收款方向、状态 3/4/5/6、未删除。
- 合同归属：`bill.contractId`，为空时取其应收登记的 `contractId`；仍为空归入“未关联合同”（按登记表或租客隔离，不按名称合并）。
- 合同纳入：全部未删除合同；合作合同（类型 7）仅在有账单时纳入。
- 每份合同按未收金额拆成三段：**逾期**（与现有总览同一规则：应收日与登记表滞纳起算日取较晚者，早于今天）、**到期未逾期**（应收日 ≤ 今天但未逾期）、**未到期**（应收日晚于今天或未设应收日）。三段之和 = 未收。
- 合同状态（互斥，按优先级）：未出账（无有效应收账单）→ 逾期（逾期金额 > 0）→ 已结清（未收 = 0）→ 未收款（已收 = 0）→ 部分已收。
- 账龄：未收金额按逾期天数分桶——未到期、未设应收日、宽限期内、1–30 天、31–90 天、90 天以上。

## 接口返回

```
ContractCollection {
  asOfDate,
  summary { contractCount, unlinkedGroups, settled, partial, unpaid, overdue, unbilled,
            receivable, received, outstanding, overdueOutstanding },
  contracts [ { key, contractId, contractCode, tenantRefId, tenantName,
                contractStatus, startDate, endDate, state,
                receivable, received, outstanding,
                overdueOutstanding, dueOutstanding, notDueOutstanding, billCount,
                fees [ { feeType, receivable, received, outstanding, overdueOutstanding, billCount } ] } ],
  aging [ { key, label, amount, billCount } ]
}
```

合同排序：逾期金额降序 → 未收降序 → 合同号；“未出账”排在有账单的合同之后。

## 前端布局

1. 页头：标题 + 账期、刷新、展开大屏。
2. 指标卡 ×4：账期应收（6 个月迷你趋势）、账期已收（收缴率）、待收合计（逾期/到期/未到期分段条）、逾期（金额 + 账单数，可点进逾期账单）。
3. 合同收款全景：左侧合同状态环形图（点击筛选），右侧合同列表（状态页签 + 搜索；分段进度条；展开看费用明细；跳转合同账单）。
4. 图表区：近六个月应收/已收柱状图（点击切换账期）、本账期费用构成环形图、欠款账龄条形图。
5. 上手区：四步流程压成一行图标，点选显示一句话说明与入口；其他台账入口为一行小按钮；统计口径收进 ⓘ 提示。

颜色沿用上一版语义：蓝 = 已收，琥珀 = 到期未收，红 = 逾期，灰 = 未到期，紫 = 保证金/未出账。
