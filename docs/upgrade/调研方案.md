# zhyq 智慧园区升级 · 对标调研方案（v2）

> 状态：方案 v2 已按用户反馈修订，待启动执行。产出形态：**先出调研报告，审阅后再一起圈定实施范围**（本轮不改任何代码）。
>
> 范围决策（用户确认 2026-07-13）：
> - 对标重心 = **国内为主 + 国际点缀 + GitHub/Gitee 开源项目**，广度 ≈ **25 家**。
> - 升级方向 = **前端设计与可视化 + 业务流程闭环 + 功能广度补齐**。
> - **AI 暂缓**：本轮不调研 AI 能力，仅在升级清单中预留扩展点/接口位（后期做 agent 很快）。
> - 调研深度边界 = 只看**架构与功能设计**；**不研究后端数据并行处理、存储、中间件等实现细节**。

---

## 1. 调研目标

对比 25 家左右国内外同类产品与开源项目，找出 zhyq 在 **功能缺口 / 流程差距 / 前端差距 / 架构设计差距** 上的距离，产出按优先级排序（P0/P1/P2）的可落地升级清单。

**调研边界（硬约束）**：
- 看：功能分类体系、业务流程/流程编排、前端设计与交互体验（权重最高）、**模块划分与整体架构设计**（开源项目可看架构图与模块组织）。
- 不看：后端数据并行处理、消息队列/存储选型细节、性能优化实现。
- AI：不作为调研维度；若顺带发现好的 AI 嵌入位（如工单智能派单入口），只记一行备注，不展开。

## 2. 调研维度（四维）

| # | 维度 | 关注什么 | 映射到升级方向 |
|---|------|---------|--------------|
| D1 | 功能分类体系 | 一级/二级菜单树、模块划分逻辑、命名体系 | 功能广度补齐 |
| D2 | 业务流程与流程编排 | 跨模块串联（招商→合同→财务→物业）、审批流引擎、自动化触发、SLA/超时升级 | 业务流程闭环 |
| D3 | 前端设计与体验 ★ | 设计体系、导航范式、工作台/驾驶舱形态、大屏风格、表格/表单交互、移动端形态 | 前端设计与可视化 |
| D4 | 架构与功能设计 | 模块边界划分、扩展点设计（插件/开放接口/流程引擎的位置）、多租户/多项目组织方式 | 支撑全部方向 + AI 接口预留 |

## 4. 执行方式

1. **并行子代理调研**：每个对象一个子代理，共 25 个，分 3 批（国内商业 8 → 国际商业 7 → 开源 7 + 前端标杆 3）。
2. **结构化卡片字段**（统一模板）：
   - 产品/项目定位与目标用户
   - 功能菜单树（尽可能还原一级/二级分类）
   - 核心业务流程编排（跨模块联动、审批流、自动化、SLA）
   - 前端形态描述（设计体系、导航、大屏、代表性交互；公开 demo/截图记录来源链接）
   - 架构与功能设计要点（模块边界、扩展点/开放接口位置；开源项目附仓库结构概览）
   - 可借鉴点 TOP5（每条注明维度 D1~D4）
   - 信息来源列表（官方文档/官网/demo/仓库 README 优先，二手文章需交叉验证）
   - （备注行）偶发发现的 AI 嵌入位，一行带过
3. **主脑汇总**：去重合并 → 每条发现映射回 zhyq 现状（**已有 / 部分有 / 没有**，对照 backend 14 模块 + 前端 14 导航基线）→ 按 价值×成本 打分 → 排 P0/P1/P2。
4. **可信度规则**：单一来源营销话术不进差距清单；功能真实性需 ≥2 个独立来源或官方文档/仓库代码佐证；开源项目以仓库实际内容为准。

## 5. zhyq 现状基线（映射用）

- 后端 14 模块：system / building / crm / tenant / contract / finance / property / todo / energy / iot / oa / hui / dashboard / auth。
- 前端 14 一级导航 + /screen 深色监控大屏；Element Plus 默认后台风（查询栏+表格+弹窗三段式）。
- 已知空白：第三方对接（支付/签章/短信/厂商平台）全为模拟；鉴权演示级；无自动化测试；无审批流引擎（合同审批为简单状态流转）。
- AI：本轮不调研，但升级清单需包含「AI 扩展点预留」条目（如统一的 agent 接入接口位、工单/报表/问答的挂载点）。

## 6. 产出物（调研报告结构）

1. **对标矩阵**：25 对象 × 4 维度总表。
2. **差距分析**：按三个升级方向各一章（前端 / 流程闭环 / 功能广度），每条差距注明出处产品与 zhyq 现状；附「架构设计差距」小节。
3. **升级建议清单**：P0/P1/P2，每条含 价值评分、成本评估（前端页面级/后端模块级粗粒度）、依赖关系；单列一节「AI 扩展点预留设计」（只定接口位，不做实现方案）。
4. **前端升级专题**（权重最高）：设计体系升级路线、导航/工作台改造、大屏进化方向、可直接参考的开源模板与交互范式清单。
5. **开源可借用清单**：哪些开源项目的哪个模块/组件可直接参考或部分移植（注明协议 License 是否允许）。
