> 版本 v1.0（2026-07-24）· 来源：2026-07-18 评审会笔记（微信聊天记录两屏，约 30 条）
> 性质：**路线图 / 整理文档**，非逐模块详细设计。确认后按波次逐个进入详细设计（brainstorming → writing-plans）。

## 0. 已确认的三个总体方向

1. **多园区切换 = 真数据隔离**。不是只做前端壳，园区间数据实隔离，影响所有模块的查询与写入。列为波次 0 地基，最先做。
2. **各类"在线解析/预览"先做框架 + 模拟**。合同解析、CAD 图预览、平面图标注、视频流、售卖机营业额爬取等重活，先把上传/存储/展示的壳与占位接口做好，后续再接真引擎。符合本项目"骨架先行、第三方占位"的一贯风格。
3. **交付先出这份正式整理文档**（路线图），确认后再挑波次深入。

## 3. 更新路径（6 波次，按依赖与风险排序）

排序原则：先打地基（多园区影响所有查询）→ 相关度高的集中做（工单）→ 敏感的隔离逐条审（财务）→ 相对独立的可并行（资产）→ 纯前端 IA 收尾。

### 波次 0 · 多园区地基（先决）
- **P1** 多园区真隔离。
- 为什么最先：园区维度一旦引入，后续所有新表都要带园区字段，所有查询都要按园区过滤。晚做则返工面巨大。
- 关键决策（详细设计时定）：复用 `tenant_id` 还是新增独立 `park_id`；数据隔离在哪一层拦（拦截器统一注入 vs 各查询显式带）；历史数据归属哪个园区。

### 波次 1 · 工单体系重构（改动最集中）
- **W1 W2 W3 W4 B1 PT1 PT2**：统一附件/图片上传 + 平面图标注定位并出 PDF + 接入审批流 + 建筑模块发起工单 + 供应商主数据 + 巡检异常转工单补强 + 巡检补图片。
- 为什么一起：都围绕"工单"这一实体，共享附件、审批、位置能力，拆开做会重复搭基础设施。
- 复用：审批流用现有 `workflow` 引擎；附件需要统一的文件上传/存储能力（本项目当前可能缺，需确认）。

### 波次 2 · IoT 设备治理
- **I4 I3 I2 I1 I5**：设备分类拆清（监控/道闸/烟感）→ 新增道闸/照明管理 → 地磅数据 → 视频流（占位）→ `acc` 便捷通行并入 iot。
- 为什么：I4 分类拆清是其余几项的前提，先正本清源再加子模块。
- 注意：视频流与原始需求"不做视频编解码"冲突，先做在线观看的占位/嵌入位，不做编解码。

### 波次 3 · 财务增强（最敏感，独立波，逐条审设计）
- **F1 F2 F3 F4 F6 F7 F8 F9**（F5 为待确认项，非功能）。
- 为什么独立：涉及金额与账单口径，项目无自动化测试兜底。硬约束：金额用 BigDecimal、状态流转条件更新、收款幂等。每条改动前单独审设计，先补该路径的测试再动。
- 口径先行：F4 收款日期口径、F8 费用类型体系、F9 采购/录入名称匹配 属于"先定义后编码"，应在写代码前敲定数据字典。

### 波次 4 · 资产 + 可视化（可并行）
- **A1 A2**：资产汇总表 + 饼图。
- 为什么可并行：只读聚合 + 前端图表，基本不碰其他模块写路径，与波次 1–3 无冲突。

### 波次 5 · 导航与归属调整（前端 IA 为主）
- **N1 H1 H2 H3 O1 E1**：投诉建议外提 + 申报服务改对外拓展 + 访客预约去重 + 活动报名统计 + 运营模块收敛 + 集抄水电系统。
- 为什么收尾：多为导航/归属调整与前端聚合，依赖前面模块稳定后再动菜单，避免反复改 `router/index.js` 与 `menu.js`（共享文件，主脑独占改）。
- 注：E1 集抄水电有后端量，若体量大可从本波拆出单列。

> **波次内并行**：同一波次里互不碰共享文件的新页面/新表可用子代理并行；`router/index.js`、`menu.js`、公共基座类由主脑独占修改。

## 4. 贯穿全程的约束与风险

- **硬约束（来自 CLAUDE.md）**：状态流转一律条件更新（`where id=? and status in(合法前态)`，`updated==0` 抛异常）；收款等幂等（业务键唯一 + SQL 原子累加）；金额 BigDecimal；新增 entity/controller/mapper 先查重类名（跨包重名 → bean 冲突启动失败）；共享文件主脑独占改；`mvn` 在 `backend/` 跑。
- **测试空白**：项目基本无自动化测试。财务/合同波次前必须先补关键路径测试。
- **文件上传能力**：多处（工单附件、图片、平面图、合同文件、资料归档）依赖统一的文件上传/存储服务。需先确认项目现状——若无，应作为波次 1 的前置基础设施先建。
- **解析引擎占位**：CAD/视频/OCR/爬取均先占位，接口位留好，真实接入是后续独立工作。
- **财务边界**：延续现有"只算只存、不写账单"原则处理新费用来源，除非专门审过设计。
