## 定位与目标用户
MicroCommunity 是 java110 团队 2017 年发起的 SaaS 化小区物业管理系统，面向物业公司，覆盖房产、业主、收费、报修、门禁道闸、停车、巡检等，已在全国 20+ 小区商业化运营，是该领域 star 数最高的开源项目。ics-park 是基于 RuoYi 体系（Spring Boot 3 + Vue）的智慧园区管理系统，面向园区运营方，主打资产/合同/账单、入驻审批、招商与企业服务，业务模型与 zhyq「园区招商-合同-账单」主线高度同构。前者代表"物业运营+硬件对接"深度，后者代表"园区资产运营"深度，二者互补，均可免费商用。

## 核心业务流程编排
按项目分述：
【MicroCommunity】1) 报修工单闭环（最有含金量的流程设计）：物业配置报修类型并绑定维修师傅 → 业主小程序/电话报修（电话登记自动定位业主房屋）→ 按报修类型配置的三种派单模式流转：手工派单（客服在工单池指派）、抢单（师傅自主抢单，适配按单提成场景）、轮询（系统定时自动派单）→ 微信模板消息通知师傅 → 师傅可维修/退回/转单 → 业主评价或退单 → 客服回访录入满意度，全链路闭环。2) 收费流程：费用项初始化（物业费/停车费按房产/车位批量绑定）→ 定时任务自动出账 → 业主微信线上缴费/物业端收款 → 缴费清单与员工收费报表 → 公众号欠费推送催缴；支持间歇性费用、按业主批量缴费、园区租金按年递增、微信线上退费直达用户。3) 审批环节为固定业务审批（小区入驻审核、投诉单审核、采购申请审批），README 声称含"工作流"模块，但非通用可配置审批流引擎。4) IoT 联动：业主成员人像照片录入后由定时任务同步至门禁设备，设备管理模块负责设备数据双向同步。
【ics-park】1) 合同全生命周期：意向合同登记（房间意向客户）→ 转正式合同 → 合同审批（走审批流）→ 生效后生成有效期内全部账单（房租/水电/物业费）→ 合同变更/作废 → 退租管理（依退租信息审批是否同意退租），与账单报表联动。2) 入驻流程：小程序提交入园申请 → 后台入驻审批 → 分配房间。3) 招商流程：招商线索登记 → 分配员工跟进跟踪。4) 服务订单：小程序申请园区服务/商城下单 → 后台订单处理发货退款。均为模块内置状态流转 + 简单审批，无独立流程引擎。

## 前端形态
【MicroCommunity】多端矩阵是其特色：PC 物业端（MicroCommunityWeb，Bootstrap + Vue，传统查询+表格后台风）、物业员工手机端 PropertyApp（uni-app 一次编码多端运行：工单维修、巡检打卡、采购领用、投诉处理、通讯录）、业主端小程序/公众号（缴费、报修、投诉），公众号承担欠费推送与公告推送触达；另有数据大屏可视化展示（停车场、巡检、报表）。开发者端独立控制台（服务/菜单/缓存/定时任务管理）是少见的"平台化"界面。演示站：http://demo.homecommunity.cn（wuxw/admin），文档站 homecommunity.cn。UI 整体偏老式 Bootstrap 后台，体验设计价值不在视觉而在多端分工与消息触达闭环。【ics-park】PC 端为 RuoYi-UI（Vue + Element UI）标准后台范式，与 zhyq 同款三段式；亮点是驾驶舱工作台（本月账单/物业费/租金/水电费多维图表 + 收款 TOP10 排行）和微信小程序 C 端（短信验证码登录、首页菜单+Banner、活动报名、在线报修进度跟踪、政策申报）。商业版演示：https://www.aicoderaft.com/（manager/123456）。

## 架构与功能设计要点
【MicroCommunity】License：Apache-2.0（明确欢迎直接商用）。Java 60% / JS 22% / Vue 17%。按业务域拆分的微服务式仓库组织（也支持 Spring Boot 单体启动）：框架层 java110-core/java110-bean/java110-db/java110-interface/java110-service 等；业务服务层按域划分——service-fee（收费）、service-order（订单）、service-community（社区/房产）、service-user（业主/用户）、service-store（商户/商圈）、service-oa（办公）、service-report（报表）、service-acct（账户）、service-job（定时任务：人脸同步/费用出账）、service-api（网关）、service-eureka（注册中心）；另有 pc-web、springboot、docs。四仓库多端架构：后端 + Web 前端 + 业主端 + 物业 uni-app 端 + 物联网系统均开源。扩展点设计突出：开发者控制台支持"配置 SQL 即生成查询接口"、菜单/权限可配置，形成轻量低代码扩展面。多租户：SaaS 模式，小区入驻+代理商审核体系。【ics-park】License：MIT。基于 RuoYi 单体架构（Spring Boot 3.5 + Sa-Token + MyBatis-Plus + Vue），目录：ruoyi-business（园区业务模块，与 ruoyi-system 框架模块清晰分界）、ruoyi-common、ruoyi-generator（代码生成器即其扩展点）、ruoyi-quartz、ruoyi-system、ruoyi-ui、ruoyi-web、sql。多租户组织：租户-多园区两级，分园区配置权限与数据隔离。审批能力内嵌于合同/入驻/退租模块，无独立流程引擎模块。

## 可借鉴点 TOP5
- **[D2流程编排]** 照搬 MicroCommunity 工单派单三模式（客服手工派单/师傅抢单/系统轮询自动派单）+ 工单池 + 转单/退回 + 业主评价 + 客服回访满意度，把 zhyq 物业工单从简单状态流转升级为可配置派单策略的闭环，回访记录直接喂给驾驶舱满意度指标
- **[D2流程编排]** 借鉴 ics-park 合同全生命周期状态机：在 zhyq 现有『合同审批→自动生成账单+锁房源』前后补『意向合同』登记（衔接招商CRM线索转化）和『合同变更/退租审批』（退租联动解锁房源+账单结清校验），三个子流程均为现有表结构的低成本延伸
- **[D1功能分类]** 以 MicroCommunity 的『车位资产（楼栋-单元-房屋-车位同级建模）+ 停车场/停车费 + 设备管理（门禁道闸设备信息+数据同步任务，人像照片定时同步至门禁）』为蓝本，补齐 zhyq 停车/门禁空白——先做资产与收费模型，设备对接沿用 zhyq 现有 IoT 模拟层即可上线
- **[D1功能分类]** 把 MicroCommunity 的收费细节移植进 zhyq 财务模块：间歇性费用、租金按年自动递增（园区长租刚需）、微信线上退费、按租户批量缴费、公众号欠费模板消息催缴，替代目前只有滞纳金的单薄账单能力
- **[D3前端体验]** 参考双端 uni-app 分工（物业员工端：接单/抢单/巡检打卡/采购领用；租户端：报修+进度跟踪/缴费/活动报名/入驻申请），为 zhyq 增设移动端触点，用微信模板消息承担工单指派与账单催缴的推送通道，PC 端保持现有三段式不动
