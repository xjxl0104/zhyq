# 对标卡片：海康威视智慧园区综合管理平台（Infovision iPark Platform，底座为 iSecure Center 综合安防管理平台）

**资料充分度**：中高：菜单树、事件中心/访客联动流程、组件化架构、OpenAPI 均有官方版本更新说明+方案文档+开放平台/开源签名库多源交叉验证；官网产品页为 JS 渲染无法直接抓取正文，前端界面细节依赖版本更新说明文字描述而非公开 demo 截图，个别 UI 描述精度有限。

## 定位与目标用户
面向制造型、商业型、服务型园区（产业园/工业园/写字楼）的一体化园区管理软件，定位是把园区内相互独立的安防、物业、办公、能耗等子系统"数据与应用融合"到一个平台，解决信息孤岛。买家是园区业主/运营方与企业行政/安保部门，交付形态为本地化部署的商用软件（iPark 构建在 iSecure Center 组件化底座之上），强项是"设备侧接入 + 安防联动"，物业/招商等运营功能相对轻。

  - 报警监测（智能报警、动环/机房监测、场所环境监测、事件中心、报警一张图）
  - 智能应用（重点/陌生/高频人员管控、封闭区域人车管控、高空抛物溯源、电瓶车秩序、客流管理）
  - 综合服务（智能巡查/定位巡查）
- 物业后勤
  - 工单中心（物业报修/报事/设备维护，待处理/已处理/我发起/抄送我，催单）
  - 会议管理、信息发布、智能柜/物资管理、食堂消费、宿舍管理
  - 消防管理、安检管理、智慧广播
- 行政办公
  - 企业考勤（班次/计划排班/假期加班规则，人脸+车辆事件作打卡数据，考勤工作台/H5/小程序）

- 运营中心

  - 事件中心（事件分级分类、预案模板库、事件归档）
  - 客流热力、安保/消防/人员态势
- 设备运维

## 核心业务流程编排
1) 事件中心是全平台流程枢纽（重点）：任何子系统（门禁/停车/消防/动环/视频AI）上报的原始事件先进事件中心，按"事件类型"配置一条处置链——启用状态→事件等级→关联标签→关联预案→关联工单；处置中支持语音播报、上传附件、事件归档；预案有统一的"预案模板库"管理。即"报警→分级分类→按类型自动挂预案+派工单→处置→归档"是一条标准化编排，而非各模块自写状态机。2) 访客联动流程：线上入园申请→审批→生成访客通行码（同时下发门禁/通道/梯控权限，限定可达区域）→到访时安保单兵扫码，系统判断能否通行并语音提示核验结果→签离回收权限；访客还可与停车场联动（车牌白名单）。3) 通行证联动门禁：员工入园申请审批通过后自动"绿码开门"，异常走人工审批，体现"审批结果直接驱动物联设备权限"。4) 违规联动：僵尸车/违停规则命中后自动把车辆推入停车场（PMS）黑名单；封闭区域人数超限/滞留超时自动预警；照明等设备事件可联动情景模式。5) 一处录入多处使用：人/组织/车辆资源统一建模，一次录入同时生效于门禁、考勤、消费、访客、停车等组件。6) 物业工单相对简单（报修/报事/催单/统计），没有租赁、账单类流程——这是它与 zhyq 互补的地方。

## 前端形态
四种前端形态并存：(1) Web 门户——集成各组件菜单的统一入口，提供"园区风格"皮肤，配置端与业务端分离（综合安防平台=用户端，运行管理中心=运维后台）；(2) 千人千面工作台——每个用户可自行编辑专属工作台/看板，支持按角色预置工作台，小部件可直接跳转事件中心处置页，可选城市展示天气/空气质量等部件（V1.4.300 更新说明，见 ejilu.cn/?id=192）；(3) 三维/大屏——三维园区驾驶舱（安保/消防/人员态势、周界防区、仿真巡检、AR 上图）、报警一张图、客流热力图，视频播放免插件；(4) 移动端——H5 门户 + 小程序 + 慧·园区 APP + 安保单兵/PDA 扫码设备。整体交互范式是"地图/三维上图 + 事件弹窗 + 反控"（在电子地图上监视、反控业务资源并联动处置），而非纯表格后台。无公开在线 demo，界面细节以版本更新说明与产品介绍 PDF（book118 6043051032005110）为据。

## 架构与功能设计要点
组件化商用平台，非开源。要点：(1) 组件化架构：组件分共性业务组件/通用服务组件/基础环境组件三层，业务按视频应用、人员通行、车辆通行、报警监测、行政后勤、智能应用、综合服务七大域切分，每个域由若干组件组合实现，各组件独立数据库，"业务扩展=新增组件"，一套平台承载不同规模项目（支持单机合并部署到分布式）。(2) 统一资源模型：人、组织、区域、车辆统一建模（LDAP 树形资源目录），保证物理资源唯一、跨组件复用。(3) 开放接口：OpenAPI 网关 Artemis（/artemis/api/...），AK/SK 签名 + HTTPS，覆盖视频取流、门禁事件、车辆、人员组织同步等域；事件订阅采用回调推送模式（eventSubscriptionByEventTypes，第三方注册回调地址，平台经 MQ 推送事件），另提供查询式接口兜底；官方发布 Java/多语言签名认证库，社区有 Python/Node 签名库（github.com/Accurio/Hikvision-OpenAPI-Signer 等）。(4) 流程引擎位置：没有通用 BPM，"编排"能力收敛在事件中心（事件类型→等级→预案→工单的配置化处置链）与各业务的审批点（访客/通行证审批）。(5) 门户/客户端/移动端三入口 + 设备接入框架统一接入设备，运行管理中心承担运维（状态监控/服务拉起/补丁/授权）。(6) 多租户弱：面向单园区/多园区联网（级联）而非 SaaS 多租户。无公开仓库，目录结构不适用。

## 可借鉴点 TOP5
- **[D2流程编排]** 照抄事件中心模式补 zhyq 的 IoT 告警空白：建统一事件中心，按事件类型可配置'等级→标签→关联预案模板→自动生成工单'的处置链并支持归档，把设备告警、投诉、消防等都收敛到这一条配置化流水线，替代各模块各写状态流转
- **[D2流程编排]** 访客/门禁闭环可作为 zhyq 第三方对接的第一个真实场景：访客申请审批通过即自动下发通行凭证（二维码/车牌白名单）、签离即回收，用海康 Artemis OpenAPI（AK/SK 签名 + 事件订阅回调）替换现有模拟对接，顺带补门禁/停车模块
- **[D3前端体验]** 把 zhyq 固定式数据驾驶舱升级为'千人千面工作台'：小部件（待办工单/待审合同/今日账单/告警）可由用户按角色自行拖拽编辑，且部件可直接跳转到对应处置页，缩短查询栏+表格的操作路径
- **[D1功能分类]** 借鉴其'综合安防/物业后勤/行政办公/运营中心/设备运维'按使用者角色分板块的导航法，把 zhyq 的 14 个平铺一级导航按'招商运营/租务财务/物业服务/设备能耗/驾驶舱'收拢成角色化板块，降低导航负担
- **[D4架构设计]** 借鉴'统一资源模型+一处录入多处使用'：把楼宇/房源/租户/人员/车辆抽成全局主数据服务，合同、账单、工单、门禁、停车全部引用同一实体 ID，避免各模块重复维护基础数据
