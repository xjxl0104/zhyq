# 对标卡片：新华三绿洲平台（H3C 智慧园区解决方案）

**资料充分度**：中：架构分层、八大主题应用、IOC"1+1"模式、报修工单与访客/会议流程均有官方多来源佐证；但 H3C 无公开产品手册/demo 展示园区应用的真实后台菜单（菜单树为据方案文重构），工单引擎细节属生态伙伴（敢为软件）能力，引擎编排逻辑公开资料有限。

## 定位与目标用户
新华三（紫光股份旗下）面向政企/产业园区的平台型智慧园区方案，采用"1+1+N"建设理念：1个IOC智能运营中心 + 1个园区数字平台（绿洲数字底座）+ N个应用系统。目标用户是园区运营方与大型企业总部/工厂园区的管理者，卖点是"平台+生态"：绿洲平台做统一物联接入、数据治理与低代码应用开发，上层园区业务应用（工单、物业、安防、通行等）大量由生态伙伴（如敢为软件IOC）在平台之上构建，而非单一自研套装软件。已在自家杭州总部园区、北京冬奥村、萧山未来工厂等落地。

  - 应用开发平台（低代码/拖拽式，业务应用微服务化）

  - 数据可视化平台（大屏/实景云图 AR）

  - 便捷通行（人员/车辆/访客通行权限打通、一卡通与移动支付拉通）

## 核心业务流程编排
1) 告警驱动的事件-工单闭环：这是该方案流程编排的核心范式。IoT 感知（烟感/水浸/环境探测）与 AI 视觉事件（区域入侵、消防通道占用、明火）产生告警 → 经 IOC 规则引擎（生态伙伴敢为软件提供任务引擎、协同引擎、配置引擎、日志引擎、权限引擎、报警引擎、工单引擎七类引擎）触发工单 → 派发处置 → 日志留痕，实现"事件触发的统一调配处理"。官方对引擎间编排细节公开描述有限，但"报警引擎+工单引擎"组合与"事件全可控、业务可全管"的闭环定位有多个独立来源佐证。
2) 物业报修工单流程（杭州总部智慧后勤）：员工线上报修 → 多模式协同推进 → 维修人员移动端作业（"高性能移动作业提高工单闭环效率"）→ 过程实时监控 → 闭环；与设备设施全生命周期管理绑定。
3) 应急联动流程：火灾场景下摄像头、烟感、门禁、安防、消防多子系统自动联动响应，IOC 应急指挥中心做预案推演、指挥调度、跨部门调度，事后数据复盘。
4) 访客全流程：预约登记 → 公众号/短信提醒 → 特定人员与车辆自动放行 → 一脸通分区权限 → 离场；VIP 走"一客一案"接待编排（抵达知会→迎宾联动→参观动线→会议→用餐→离场）。
5) 会议室全流程：会前一键预约+设备预热预检 → 会中音视频协同 → 会后资源自动释放、会议纪要自动整理。
6) 无审批流产品化描述：公开资料未见通用审批流/BPM 引擎作为独立卖点，流程编排主要靠 IoT 联动规则 + IOC 事件引擎，OA 类审批不在其方案叙事内。

## 前端形态
全渠道形态明确分层：(1) IOC 巨屏——C/S 桌面程序 + 巨屏多窗口融合、多屏互动、多工作站协同渲染，数字孪生三维（建筑/设施/设备三维重现、虚实映射）、AR"实景云图"（AI+AR 在实景视频上叠加数据标签）、自然语音与多点触控交互；(2) B/S 管理后台——绿洲平台 Web 控制台（oasis.h3c.com 可见登录入口，按"业务专区"组织：网络管理、智能运维、业务组件、应用中心，应用以组件市场方式订购启用）；(3) 移动端——APP + 小程序 + 公众号，园区企业与个人用户"一个手机APP"接入报修、访客、会议室等全域服务，维修人员用移动作业端处理工单。设计体系无公开规范文档；大屏以数字孪生深色驾驶舱为主流形态，且明确拆成"日常运行监测"与"应急指挥"两块（1+1）。公开 demo：绿洲平台登录页 https://oasis.h3c.com （需账号，无园区应用公开体验）。

## 架构与功能设计要点
典型"平台+应用"分层，而非一体化套装软件：底层为物联接入层（绿洲物联网平台，南向对接 50+品牌子系统、200+种终端，协议覆盖 MQTT/CoAP/自定义TCP/UDP/Modbus/Zigbee/LoRaWAN/NB-IoT，内置蓝牙/RFID/UWB 定位引擎，北向以 MQTT 订阅 + REST API 开放数据）；中层为绿洲数字平台三大件——融合集成平台（数据+API 非侵入式集成，打通 IT&OT 与既有业务系统，这是其"去烟囱"的关键扩展点）、数据运营平台（采集/开发/资产/服务全生命周期，建主题仓库沉淀园区数据资产）、应用开发平台（低代码拖拽式开发，业务应用微服务化，"快速定制业务逻辑和交互界面"的应用层 PaaS）；上层为 N 个场景应用 + IOC。流程引擎位置：不在平台核心，而在 IOC 应用层由生态伙伴引擎（敢为七引擎）承担。多租户/总分组织：支持"总部-分支"数字化统筹（烟草案例）。生态开放是设计重点：绿洲 3.0 对接 200+ ISV、沉淀 35 个应用场景套件（综合安防、便捷通行、用户画像等），行业能力以"场景套件"复用。无开源仓库。边界启示：H3C 把工单/物业等业务应用外包给生态，自己只做接入、数据、开发三层平台能力。

## 可借鉴点 TOP5
- **[D2流程编排]** 把 IoT 告警/设备事件与物业工单打通：参照其"报警引擎→工单引擎"范式，在 zhyq 增加联动规则（告警类型+位置→自动生成工单并按区域派单），把现有 IoT 告警模块和工单模块从两个孤岛变成事件闭环
- **[D2流程编排]** 工单补移动作业闭环与过程监控：为维修工提供移动端（H5/小程序）接单-到场-完工拍照-评价链路，并把响应时长、闭环率等指标上到 /screen 大屏（对应其"高性能移动作业提高工单闭环效率+过程实时监控"）
- **[D3前端体验]** 大屏采用"1+1"双模式：/screen 在日常运行监测视图外增加应急指挥视图（事件详情+关联摄像头/门禁/人员+处置动作按钮），事件触发时可跨模块联动处置而非只做展示
- **[D1功能分类]** 补资产管理模块并复用现有 IoT 能力：资产台账+位置追踪+越界告警自动触发工单/监控联动（其智慧办公用 RFID 实现"位置可查、越界联动告警"），正好填 zhyq 已知空白
- **[D4架构设计]** 把第三方模拟对接收敛为统一集成适配层：参照绿洲融合集成平台"非侵入式集成"思路，定义统一的设备/系统 connector 接口（协议适配+物模型+事件标准化），使门禁/停车/能耗等真实对接可插拔接入而不改业务代码
