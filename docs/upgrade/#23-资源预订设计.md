# #23 统一资源预订域设计 · 待实施（本轮自主）

> 版本 v0.1（2026-07-15）· 批次④ P1 · 无强依赖
> 后端+前端。**费用只算金额存预订记录，不自动写账单**（避开财务，与 #11/#21 停车费同理，并入账单留后续）。

## 1. 目标与非目标

**目标**：把散落的 会议室预约(property/meeting)、场地预约(srv_site_booking) 统一成**一套资源目录 + 日历预订**：资源(会议室/场地/工位) 一张目录表，预订一张记录表，时段冲突校验，Booking Policy 按资源+时长算费用金额（挂预订记录，不写账单）。

**非目标**：不做审批流（预订直接生效）；**不自动生成账单/收款**（费用只算金额，财务并入留后续）；不迁移删除既有 meeting/srv_site_booking 表（叠加统一层，本轮不强迁）；不做资源图形化排布。

## 2. 现状锚点（后端地图）

- `property/meeting/{room,booking}`：会议室 + 预约，**booking 有时段冲突校验**（可复用其冲突校验思路）。

## 4. 组件

- 实体 `Resource`/`ResvBooking`（避重名）+ Mapper（`*.mapper` 包）。
- **BookingService**：
  - `book(booking)`：**时段冲突校验**（同 resource_id、status=已预订、时段重叠 `start < :end AND end > :start` → 拒 BizException，复用既有思路）；算 fee=ceil(时长小时)×price_per_hour（price 空则 fee=null）；insert。事务内查重防并发。
  - `cancel(id)`：status→2（释放时段）。`finish(id)`：status→3。
- **BookingPolicy**：本轮=纯函数 `calcFee(hours, pricePerHour)`（含 JUnit）。不做策略矩阵。
- ResourceController(`/rsv/resource` CRUD) + BookingController(`/rsv/booking` book/cancel/finish/page，按日期查某资源已订时段供日历)。
- 前端：资源目录页 + 预订日历/时段页（Element Plus，不强上专业日历库）。

## 5. 零触碰 & 决策（费用边界）

- 零触碰：全新 rsv_* 表与模块，不改 property/meeting、srv_site_booking、finance 任何代码。
- **D1 费用（关键边界）**：`fee` 只在预订记录上算并存，**绝不写 fin_bill / 触发收款**。并入账单留后续财务轮（与用户 defer 的 #11 同域）。
- D2 冲突校验：时段重叠拒绝，事务内查重防并发。
- D3 不强迁旧预约数据：叠加统一层，旧预约照旧。
- D4 审批：预订直接生效（无审批流）。
