## 1. 目标与非目标

**目标**：补齐"便捷通行"这一档产品普遍有、zhyq 空白的模块——三块最小可用：
1. **门禁通行记录**：谁/哪个门/何时/进或出/放行或拒绝，可查、可按空间(#3)/人筛。
2. **访客预约与到访**：登记预约 → 到访签到 → 离场，状态机流转。
3. **停车**：车辆登记 + 进出场记录 + **停车费试算**（按时长×费率，只算只存）。

**非目标（本期不做）**：真实硬件对接（走 #2 适配器 Mock 位）、车牌 OCR、人脸识别、停车费并入账单收款（碰财务，缓办）、租户小程序端（#22 排除）。

## 4. 服务逻辑

### AccVisitorService（状态机，条件 UPDATE 抢状态，沿用 #13/#20 手法）
- `reserve()` → 建预约(status=1)。
- `checkin(id)` → 1→2，记到访。
- `leave(id)` → 2→3。
- `cancel(id)` → 1→4（已到访不可取消）。

### AccParkingService
- `enter(plateNo, ownerType)` → 建在场记录(status=1, enterTime=now)。同车牌已在场则拒绝（条件查重）。
- `leave(id)` → 2，leaveTime=now，**调 `ParkingFeeCalculator.calc(enter,leave,rule)` 存 fee**。
- `ParkingFeeCalculator.calc(enterTime, leaveTime, rule)` — **纯函数，带 JUnit**：按时长×费率、首 N 小时免费封顶等；null 时间→null。**只返回金额，不写任何财务表**。

### AccAccessService
- `record(gateCode, personType, personRef, direction, result)` → 插一条通行流水。裸插，无状态机。

### 门禁硬件（Mock，走 #2 适配器）
- 通过 `ConnectorRegistry` 取 `DeviceConnector` Mock，`record()` 时可选调用 Mock 开门——本期只落记录，硬件动作是 Mock no-op。
