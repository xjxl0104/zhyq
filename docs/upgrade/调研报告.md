# zhyq 智慧园区升级 · 对标调研报告

> 版本：v1.0（2026-07-13）· 状态：**待用户审阅**，审阅后一起圈定实施范围（本轮未改任何代码）
> 输入：25 家对标结构化卡片（`cards/01~25`，355 次检索、≥2 源交叉验证）+ 四章专题差距分析（`drafts/D1~D4`）
> 范围（已确认）：国内为主+国际点缀+开源；只看功能分类/流程编排/前端设计★/架构与功能设计；不研究别人后端数据处理实现；**AI 暂缓，只预留扩展点**

---

## 1. 执行摘要

**一句话结论：zhyq 的「招商→合同→财务→物业」主链路功能面在同档产品中不落后，真正的差距不在缺页面，而在缺四种「连接组织」——事件联动、审批链、设计体系、对接适配层；补上它们，现有 77 个页面就能从「模块集合」变成「一个产品」。**

四个维度各一句话：

| 维度 | 结论 |
|---|---|
| D1 功能广度 | 主链路不缺；模块级空白集中在 **资产管理、便捷通行（门禁/访客/停车）、租户自助端** 三处；14+ 平铺导航是「Demo 感」最大来源，业界共识是收敛为 5~9 业务域两级 |
| D2 流程闭环 | 「合同→账单→锁房源」主干成形（同档开源中仅 ics-park 可比）；断点在 **事件-联动规则中心、轻量审批链、催缴任务流、工单 SLA 超时升级** 四处，12 家对标共同验证「事件模型+规则表+审批链」渐进路径，无需先上重型 BPM |
| D3 前端体验★ | 差距不在技术栈而在范式：缺 **设计 token 地基、标签页路由、schema 表格封装、角色工作台、记录详情页**；大屏走「组件标准化→JSON 配置化+中屏下沉→事件处置工作台」三步；核心方案全部可从 MIT 同栈项目（vue-pure-admin/soybean-admin/GoView/DataV）直接搬 |
| D4 架构设计 | 缺四根「骨架」：**第三方对接适配器层（消灭全模拟）、统一领域事件、统一空间树主数据、指标/开放 API 层**；补齐后 D2 流程与 D3 前端都有了承载位，AI agent 也有了挂载点 |

**横切前置项**：登录鉴权补强（Spring Security + JWT 级别）是租户小程序、开放 API、大屏免登分享三件事的共同前置，建议与首批实施同排期。

## 2. 调研概况

- **对象（25 家）**：国内商业 8（华为、腾讯微瓴、阿里云、明源云、海康、新华三绿洲、特斯联、蘑菇物联）；国际商业 7（JCI OpenBlue、Schneider EBO、Siemens Building X、Honeywell Forge、IBM TRIRIGA/Planon、Yardi、OfficeRnD/Nexudus）；开源 7（yudao、JeecgBoot、Odoo、openMAINT/CMDBuild、ThingsBoard、Snipe-IT、MicroCommunity/ics-park）；前端标杆 3（AntD Pro/Lightning、soybean/pure-admin、GoView/DataV）。
- **方法**：每对象一个并行子代理，统一卡片模板（菜单树/流程编排/前端形态/架构要点/可借鉴 TOP5/来源/可信度自评）；功能性结论 ≥2 独立来源或官方文档/仓库佐证，厂商单方营销话术不计入。
- **对 zhyq 最有对照价值的对象**：明源云（招商-合同-账单闭环最贴）、Yardi（财务流程国际范式）、OfficeRnD/Nexudus（体量最接近的 SaaS 形态）、海康（事件中心范式）、ThingsBoard（告警模型可照抄表结构）、ics-park/MicroCommunity（同领域开源、部分表结构可移植）、vue-pure-admin/soybean/GoView（完全同栈前端方案）。
- 25 对象 × 22 功能域完整对标矩阵见 `drafts/D1-功能广度差距.md` §1。

## 4. 四章差距分析（摘要，详见 drafts/）

- **D1 功能广度**（`drafts/D1-功能广度差距.md`）：22 个功能域对标，zhyq「已有」12 域、「部分有」6 域、「没有」4 域；覆盖率最高的缺口依次是 租户门户/移动端（12 家有）、资产管理（11 家）、门禁访客闭环（8 家）、停车（6 家）；信息架构建议 14 平铺 → 9 业务域（工作台/空间与资产/招商租赁/财务/物业服务/便捷通行/能源与物联/园区运营/系统管理）。
- **D2 流程闭环**（`drafts/D2-流程闭环差距.md`）：主链路六段逐段对照；四大流程能力（审批引擎/联动编排/SLA/财务自动化）现状全为「没有或部分有」；对标共同范式=「事件→规则→动作」一张规则表 + Odoo 式轻量审批链，重型 BPM 可后置。
- **D3 前端专题**（`drafts/D3-前端升级专题.md`）：五层差距（设计体系/导航工作台/表格表单/主题/移动端）+ 大屏四台阶进化路线 + 五步渐进改造路线图（token→框架→组件→页面范式→可视化，每步独立可交付可回退，业务 api 层全程不动）。
- **D4 架构与开源**（`drafts/D4-架构与开源可借用.md`）：四根骨架（适配器层/领域事件/空间树/指标与开放 API）+ 审批引擎架构定位 + 模块契约规则 + 多园区两级演进；AI 扩展点 A1~A8 清单；12 个开源项目逐一给出 License 与借用方式。

## 5. AI 扩展点预留（本轮只留位，不实现）

对标共识：头部产品的 AI 全部**内嵌在既有业务动作旁**（按钮/钩子/事件/建议卡），没有独立"AI 模块"。zhyq 预留三类位（详见 D4 §4.2 A1~A8）：

1. **事件挂载点**：工单流转钩子（智能派单/处置建议）、告警 enrich 钩子（归并降噪）——随批次①#1 事件最小集顺手预留；
2. **API 接口位**：统一指标 API 占位（将来 agent 问数）、`/api/agent/chat` 空网关路由、附件解析回调（合同抽取/票据 OCR）；
3. **前端插槽**：顶栏问答助手按钮位、待办「建议卡」类型（source=agent 可一键转工单）、大屏 JSON schema（将来 AI 生成大屏配置）。

全部是「顺手留位」，边际成本接近零；后期做 agent 时不动架构。

## 6. 开源可借用要点（License 红绿灯）

- ✅ **可引代码/移植表结构**（MIT/Apache）：vue-pure-admin（@pureadmin/table、useTags、按钮权限——落地成本最低）、soybean-admin（主题系统）、GoView/DataV（大屏组件与 JSON 渲染架构）、ThingsBoard（告警模型表结构照抄）、yudao（BPM 业务表单模式、多租户组件）、MicroCommunity（停车/收费表结构）、ics-park（多园区模型）、JeecgBoot 主仓（local/cloud-api 双实现样板）。
- ⚠️ **只参考设计、不引不抄代码**（AGPL/商业协议）：Snipe-IT、openMAINT/CMDBuild（资产/维保模型蓝本）、Odoo 企业版与 OCA、JeecgBoot 商业版功能、JimuReport。
- 默认姿势：**参考设计 + 同栈前端包引依赖 + 表结构级部分移植**，符合 zhyq「从零手写不套底座」原则。

## 7. 建议的决策点（等你拍板）

1. **批次顺序确认**：建议按 ①地基 → ②流程 → ③前端 → ④广度 推进（前端权重虽最高，但 token/标签页已提前进 ①，其余前端范式吃 ② 的流程数据红利更划算）；也可 ①+③ 并行先跑「纯前端可见」的改造。
2. **鉴权补强（#7）排期**：是随批次①做，还是单独先行？（小程序/开放 API/免登分享都卡它）
3. **批次④的取舍**：资产、通行、小程序三个新模块是全要，还是先做其中一两个？
4. P2 池何时启动、每批投入的子代理规模。

## 8. 实施预算预估（2026-07-13，Opus 4.6 编码 + Fable 5 审查）

官方牌价：Opus 4.6 = $5/$25 每百万 token（输入/输出，与 4.7/4.8 同价）；Fable 5 = $10/$50；缓存读≈0.1× 输入价。估算（含缓存折扣）：批次① ~$110–150 · 批次② ~$90–120 · 批次③ ~$150–220 · 批次④ ~$130–200 → Opus 编码小计 ~$480–690；Fable 5 每批审查+主脑规划集成 ~$150–210。**全量总计 ≈ $650–900 牌价（中位 ~$750）；仅批次①+② ≈ $350–450。** 误差 ±50%（主要变量：财务/合同逻辑返工、77 页迁移自动化程度）；走中转实付通常远低于牌价。省钱打法：共享文件主脑独占、子代理 prompt 稳定保缓存、每批全绿再进下一批、批次②先 Fable 审设计再放 Opus 动手。
