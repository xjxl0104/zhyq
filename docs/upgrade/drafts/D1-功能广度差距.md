# D1 · 功能分类体系与功能广度差距

> 依据：25 张对标卡片（cards/01~25）+ zhyq 现状基线（backend 14 模块 / 前端 14 一级导航 + /screen，77 页面实测）。
> 边界：只谈功能面（有什么/缺什么/放在哪），流程闭环归 D2、前端形态归 D3、架构与适配层归 D4；不涉及后端数据并行处理实现；AI 仅以「扩展点预留」出现。
> 标注口径：对标产品 ●=有（核心能力） ◐=部分有/靠生态或外接 ○=无；zhyq 现状 = **已有 / 部分有 / 没有**。

---

## 0. zhyq 功能基线（对照锚点）

- 后端 14 模块：system / building / crm / tenant / contract / finance / property / todo / energy / iot / oa / hui / dashboard / auth。
- 前端 views 实测 16 目录 77 页：building(项目/楼宇/租控)、crm(线索/客户/渠道/佣金/计划/分析)、contract(列表/归档/设置)、finance(账单/收款/逾期/发票/流水/报表等 10 页)、property(工单/会议室/巡更/三检/资产/投诉/问卷/活动)、energy(表计/统计)、iot(设备/告警/点位/通道/厂商/分类)、oa(任务/审批/考勤/公告等 9 页)、service≈hui(访客/通行证/放行条/商城/政策/申报/场地预订/论坛等 11 页)、tenant(租户/员工/消息)、system(用户/角色/菜单/消息中心等 8 页)、data(数据中心/报表/剖面图)、dashboard、screen、app(应用中心)。
- 与调研方案基线的差异说明：`property/Asset.vue` 已有**单页资产台账**（编码/分类/采购价/保修/责任人/位置），`service/SiteBooking.vue` 已有**场地预约**（含费用字段），`system/MessageCenter.vue` 已有**消息模板+渠道**概念（发送为模拟）——因此资产、场地预订、消息中心按「部分有」而非「没有」计。
- 已知空白（方案口径）：第三方对接全模拟、鉴权演示级、无审批流引擎、无移动端/C 端。

## 3. 导航/信息架构重组建议

### 3.1 对标分类法对照

| 对标 | 分类法 | 一级数量 | 划分逻辑 |

| 明源云 | 资产管理/租赁管理(招商-交易-财务)/园区运营 + 平台 | 3+1 | 按业务域，租赁域内再分三段 |

**共识**：没有一家把 14+ 个模块平铺在一级导航；主流做法是收敛为 **5~9 个业务域两级结构**，且按角色裁剪可见板块（海康五板块、TRIRIGA 角色门户、Yardi 角色导航）。

### 3.2 zhyq 现状问题

- 前端实际已有 **16 个 views 目录**（14 导航 + data/app 溢出），且模块归属有历史遗留：访客/通行证/场地预订挂在「惠企 service」下、资产台账挂在 property 下——与对标的「便捷通行」「资产管理」独立成域的归类法不符。
- 所有角色看同一份平铺菜单，无角色板块（对照海康/TRIRIGA/Yardi，zhyq **没有**）。

### 3.3 重组方案（14 平铺 → 9 业务域两级）

| # | 建议一级域 | 收纳的现有模块/页面 | 对标依据 |
|---|---|---|---|
| 1 | 工作台 | dashboard + todo(升级为待办+审批中心 G8) + data 报表 + /screen 入口 | 海康运营中心、明源超级工作台、AntD Pro workplace |
| 2 | 空间与资产 | building(项目/楼宇/租控/剖面) + **asset 新模块(G2)** | 明源「资产管理」域、openMAINT 空间资产台账、华为资产场景 |
| 3 | 招商租赁 | crm + contract + tenant | 明源「租赁管理」（招商-交易一体） |
| 4 | 财务 | finance（10 页保持） | 明源租赁域财务段、Yardi Financials |
| 5 | 物业服务 | property(工单/巡检三检/投诉/问卷/活动) + 资源预订(G6：会议室+场地+工位) | 海康物业后勤、H3C 数字后勤 |
| 6 | 便捷通行 | **新域(G3/G4)**：访客/通行证/放行条(从 service 迁入) + 门禁 + 停车 | 华为「便捷通行」、海康「人员/车辆通行」 |
| 7 | 能源与物联 | energy + iot(含 G12 子系统接入位) | 海康设备运维、H3C 智慧能源/环境、华为能效+设施 |
| 8 | 园区运营 | hui/service 剩余(政策/申报/商城/论坛/生态/IP) + oa | 明源园区运营、H3C 智慧办公、海康行政办公 |
| 9 | 系统管理 | system(用户/角色/菜单/字典/消息中心/审计 G10) + app 应用中心 | 各家 Setup/Admin 惯例 |

- **两级结构 + 角色板块**：一级域进顶栏、二级进侧栏（实现形式=D3 P1-1 mix 导航），并按角色预置可见域集（招商运营→2/3/4，物业→5/6/7，管理层→1）——对齐海康五板块与 Lightning App 分组。
- **兼容策略**：仅动导航树与路由分组，不动后端 14 模块包结构（后端归属调整只发生在 asset 迁出 property、通行页迁出 hui 两处，属 G2/G4 交付内容）。
