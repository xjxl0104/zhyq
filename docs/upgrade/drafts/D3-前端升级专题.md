# D3 前端设计与体验升级专题（权重最高章）

> 输入：25 张对标卡片（docs/upgrade/cards/）+ zhyq 前端现状实测。
> 边界：只谈前端设计与交互形态，不涉及后端数据并行处理实现；AI 仅以「扩展点预留」形式出现。
> 评分口径：价值(高/中/低) × 成本(大/中/小)，成本按前端页面级粗粒度估算。

---

## 0. zhyq 前端现状基线（实测）

- 技术栈：Vue 3.4 + Vite 5 + Element Plus 2.7 + Pinia + Vue Router 4 + ECharts 5 + Sass，pnpm。
- 布局：`frontend/src/layout/` 仅 1 个 `Layout.vue` + 手工维护的 `menu.js`，**14 个一级导航平铺**，单一布局模式，无标签页路由，无主题配置。
- 页面：77 个页面几乎全部为「查询栏 + 表格 + 增删改弹窗」三段式（Element Plus 默认亮色后台风）；详情查看以弹窗为主，无记录详情页范式。
- 大屏：`views/screen/BigScreen.vue` **单文件手写**，深色指挥中心风，数据来自真实后端聚合接口，秒级刷新时间；无下钻、无配置化、无分享链路，与后台亮色主题是两套割裂样式。
- 移动端：无任何移动端/租户自助端形态。
- 权限：仅菜单级，无按钮级权限控制。

## 2. 大屏 / 可视化升级路线

### 2.1 对标结论：大屏的四个进化台阶

以 /screen 现状（深色指挥中心风、手写单文件、秒级刷新、只读展示）为原点，对标产品呈现四级台阶：

1. **视觉层标准化**（GoView/DataV）：科技感边框/装饰/数字翻牌/轮播表组件化；1920×1080 设计稿 + `transform:scale` 等比缩放自适应（取宽高缩放比较小值、origin 左上、resize 防抖，预判 DPI 150% 问题），比例不定时降级 X/Y 轴滚动。zhyq 现状：手写卡片容器，自适应方案未标准化——**部分有**。
2. **配置层**（GoView「大屏即一份 JSON」、Honeywell「widget 注册制」、Schneider「widget 化 + 公共/个人两级 + 轮播」、微瓴「IOC 主题模板一键生成」、Siemens Data Visualizer 独立仪表盘搭建器）：卡片抽象为 `{组件名, 布局, 样式, 数据源(API+刷新间隔+过滤器)}` 的 JSON schema 统一渲染；数据源未接入的 widget 置灰并提示原因（正好消化 zhyq「第三方对接全模拟」现状）；组件粒度独立轮询（告警 5s、能耗 5min）替代整页统一拉数。zhyq 现状：**没有**。
3. **交互层**（ThingsBoard「Dashboard States 分层钻取 + 实体别名复用」、DataV 蓝图编辑器「事件→逻辑节点→动作」、GoView「控件→注入请求参数」联动、蘑菇物联/华为 IOC「园区→楼宇→楼层→设备层层穿透」）：顶部园区/楼宇下拉控件驱动全部卡片联动下钻；同一套模板经数据源别名复用到不同楼宇。zhyq 现状：**没有**。
4. **处置层——从展示屏到事件处置工作台**（华为 IOC「事件点位拉起周边监控、一键启动预案」、特斯联「状态全可视、事件全可控」大屏可下发指令、H3C「日常监测 + 应急指挥」双模式、蘑菇 MoguV 大屏直接反控、JCI 在 3D 上下文中叠加告警）：告警按楼宇/楼层平面落点渲染，点击下钻设备详情+关联工单+一键派单。zhyq 现状：**没有**（挂现有工单 API 即可起步，不需要 3D）。

### 2.2 三条关键教训（来自对标）

- **华为「大中小屏」教训：大屏离管理者太远，看得少用得少**。应把大屏指标卡拆成可复用驾驶舱组件，嵌入各一级模块首页做「中屏」部门驾驶舱并支持点击下钻列表页，而不是只维护一块孤立 /screen。明源「一屏一板一讯」同一结论：大屏给决策层、看板给模块首页、讯报做推送，指标口径共用一套定义（微瓴「指标发布为 API、大屏与驾驶舱统一消费」同理）。zhyq 现状：**部分有**（dashboard 与 screen 各写一套聚合）。
- **数字孪生/3D 不是必需品**。JCI/微瓴/特斯联的 3D 是「场景内上下文视图」而非全局皮肤；zhyq 已有楼宇房源数据，可用 2D 楼层平面图/2.5D 剖面图叠加「租控色块 + 能耗热力 + 告警点位」三层切换，作为 3D 的低成本替代（特斯联卡片明确此路线；zhyq 已有剖面图页 SectionView.vue 可扩展）。
- **大屏需要免登分享链路**。DataV 带时效 HMAC-SHA256 签名 URL（时间戳+签名参数，防篡改防过期）；ThingsBoard 仪表盘公开链接免登只读——园区展厅/招商接待屏刚需。zhyq 现状：**没有**（且当前鉴权演示级，须与鉴权补强同排期）。

### 2.3 升级路线建议（三步走）

1. **第一步（组件库嵌入范式，1-2 周量级）**：/screen 引入 DataV 系边框/装饰/数字翻牌/轮播表（MIT，Vue3 用 GoView 重写版或社区 datav-vue3），标准化 transform:scale 自适应，卡片改组件粒度独立轮询；告警轮播表用 updateRows 行级热更新。
2. **第二步（JSON 配置驱动 + 中屏化）**：卡片抽象为 JSON schema 统一渲染（借鉴 GoView 渲染架构：配置即大屏，可导入导出）；同套指标卡组件下沉到 dashboard 和各模块首页；顶部空间维度控件实现全屏联动下钻（园区→楼宇）。
3. **第三步（平台搭建范式，按需）**：需要多屏（招商/能耗/安防/物业专题屏）时，或 iFrame 嵌入 GoView 编辑器（yudao 已验证该集成路线：URL 透传 token），或基于第二步 JSON schema 自建轻量拖拽编辑器；同时补免登签名分享。**不建议第一步就上完整低代码搭建平台**——zhyq 单园区场景下配置文件 + 模板足够。
   - （AI 扩展点预留一行：大屏 JSON schema 天然是「AI 生成大屏配置 + 编辑器兜底」的挂载位，参照 DataV 7.0 / GoViewPro 模式，本轮只留 schema 接口不做方案。）

### P0（本轮必做：低成本高杠杆，全部不动业务逻辑）

| 编号 | 建议 | 出处产品 | zhyq 现状 | 价值×成本 | 一句理由 |

### 设计体系升级路线（分步，不动业务逻辑的渐进式改造）

```
第 1 步  token 地基（P0-1）
  定义语义 CSS 变量层 → 映射 Element Plus 变量 → 主题配置抽屉（亮/暗/主题色）+ localStorage 持久化
  验收：任一页面零改动情况下可一键切暗色；/screen 改读同一套 token。
第 2 步  框架层（P0-2 / P1-1 / P1-7）
  标签页路由 → mix 导航 + meta 驱动菜单 → 命令面板
  验收：路由/菜单/权限收敛到一份配置；跨模块操作不丢状态。
第 3 步  组件层（P0-3 / P1-6）
  useCrudPage 表格封装先在 1-2 个新页面试点 → 按模块渐进替换 77 页（每页只改模板不碰 api 层）→ 按钮权限指令随替换同步落
  验收：新页面代码量减半；列设置/密度/批量操作全站一致。
第 4 步  页面范式层（P0-4 / P1-2 / P1-4 / P1-5）
  角色工作台 → 合同记录页试点（Path 阶段条）→ 工单 Triage → 租控平面图
  验收：主链路（招商→合同→账单→工单）全程不再依赖「列表+弹窗」完成。
第 5 步  可视化层（P0-5 → P1-3 → P2-3/P2-4，见 §2.3 三步走）
原则：每步独立可交付、可回退；业务 api 层与后端接口全程不动；
     第 3 步开始的页面替换按「模块灰度」推进，避免一次性重写。
```

（AI 扩展点预留备注，一行：工作台卡片流、命令面板、大屏 JSON schema 三处是天然的 AI 挂载位——AI 助手一级入口已成 AntD Pro v6 标配页面模板，本轮仅在路由与 schema 上留位，不展开方案。）
