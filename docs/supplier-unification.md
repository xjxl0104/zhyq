# 供应商档案合并与授权界面调整

## 操作入口

- 用户管理：先选角色，再按模块、功能、操作设置额外授权。角色权限有来源标记，不再在选择角色时复制为直授权限；已有用户的直授记录保留。角色管理使用相同分组和搜索。
- 物业服务 → 物业 → 供应商档案：替代原责任单位及预算下的供应商档案。原预算档案地址自动转到新入口。
- 点击供应商名称或“详情/合同”可查看该供应商的合同并新增合同。在主合同旁点击“加补充协议”，会带入供应商及主合同。合同和补充协议各自保留附件与状态。
- 补充协议必须关联同一供应商的主合同，关联保存后固定。存在补充协议的主合同不能删除或改换供应商。供应商有关联合同或工单时不能删除。

## 数据迁移

V76 增加供应商物业字段、工单供应商关联、合同主协议关联，扩大备注长度。V77 回填资料和工单关联，V78 转换原责任单位授权并停用旧权限。

匹配规则：同租户、名称完全相同、两侧名称均唯一且原单位为全局单位时关联现有供应商，只补齐空字段。其他情况独立建档，保留园区及类型。已删除单位为历史工单保留归档档案。迁移编号使用 `LEGACY-GYS-` 前缀，避免干扰现有自动编号。原 `pm_responsible_unit` 表及工单旧关联列保留用于追溯。

原“保存”授权转换为供应商新增、修改、状态操作；查询、删除按对应操作转换。合同权限单独配置。现有登录会话应重新登录，以取得迁移后的权限。

## 合入 main 前

仓库 main 自动部署，本次包含数据回填。先按现有部署方式停写并备份数据库，再核对生产 `flyway_schema_history` 中的版本，确认 V76–V78 未被占用。

以下命令由部署人员替换数据库连接信息执行，密码使用交互输入：

```sh
mysql -h DB_HOST -u DB_USER -p zhyq_park -e 'SELECT version, description, success FROM flyway_schema_history ORDER BY installed_rank DESC LIMIT 10'
mysqldump -h DB_HOST -u DB_USER -p --single-transaction --routines --triggers --events zhyq_park > zhyq_park_before_supplier_merge.sql
```

本次未连接生产数据库，也未执行上线。回滚需连同应用及备份恢复；不可只回退前端后继续使用旧责任单位写入口。旧表和旧列暂不删除。
