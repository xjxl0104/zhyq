# 云仓三维首页

## 打开预览

在仓库根目录运行 `./start-twin-preview.ps1`，然后打开 <http://127.0.0.1:5273/twin-preview>。也可以进入 `frontend`，执行 `pnpm install` 和 `pnpm dev --host 127.0.0.1 --port 5273 --strictPort`。

查看嵌在原系统蓝色侧栏中的效果：运行 `./start-twin-preview.ps1 -Layout`，打开 <http://127.0.0.1:5323/dev/twin-layout.html>。这个开发验证入口使用原 `Layout`、`TwinDashboard` 和项目选择器，项目数据由隔离的内存适配器提供，不向后端发送请求，也不写入登录 token。所有业务入口在此只显示目标路径；正式业务仍须登录原系统。它使用独立端口避免影响主预览的本地存储，未列入生产构建入口。

预览不依赖数据库或后端，不写入登录 token。开发环境之外不注册 `/twin-preview`。正式 `/dashboard` 现在位于原 `Layout` 的子路由中，受原有登录守卫保护，原经营看板保留在 `/overview`。

`TwinDashboard.vue` 从原项目 Store 读取当前项目；`TwinHome.vue` 在正式首页隐藏独立预览侧栏，沿用原 Layout 的完整菜单、项目初始化/切换和退出登录。三维首页从 KeepAlive 排除，离开时释放 WebGL。当前仍展示参考模型，不代表所选项目已完成模型或业务数据绑定。

## 可以体验什么

- 三维场景铺满运营工作区，左右叠加半透明出租率、租金、工单、安防、待办和能耗卡片；点击楼层条与待办定位模型，点击卡片入口跳转原模块。短桌面窗口收起重复的顶部指标，保留完整七层出租率和业务入口；“专注模型”可暂时隐藏面板并放大模型。菜单与面包屑统一为“首页”。
- 连续道路、路口、斑马线、围栏、路灯及参考实景的 DIPARK 门楣、圆角玻璃岗亭、道闸；“入口视角”直接查看大门。
- 晴天、阴雨、夜景三种本地天气模拟；天空、雾、灯光、湿路面及面板配色联动，雨天有降雨效果，夜间有窗光和路灯。未连接实时天气服务。
- 拖动旋转、滚轮缩放、右键平移；工具栏支持缩放、复位、自动环绕、标签开关、全屏。
- 建筑外观、楼层展开、单层室内三个模式；直接点击建筑或楼层按钮选择楼层。
- 室内可查看示意柱网、梁、风管、消防管线、消火栓和仓储分区。
- 底部六类业务图层筛选点位。点击点位文字查看详情，点击其右侧箭头直接进入关联模块。
- 本地模块展示示例记录，支持「定位模型」往返。正式首页的入口映射到已有业务路由。
- 搜索空间名称和设备编号、查看十一份实景与招商参考资料、导出当前视图的 GLB 模型。

## 模型和数据口径

外观根据用户提供的十张实景照片及一张招商资料程序化建立底稿，再在本机 Blender 5.2.1 中整理分组、调整 PBR 材质及添加可编辑倒角修改器。网页实际加载 Blender 导出的 `frontend/public/models/dipark-warehouse.glb`，不是渲染图片。楼层按照新提供的招商资料修正为 7 层，层高分别为 12m、9.5m 和五层 6.6m（主体总高 54.5m）。园区名称为 DIPARK 数智云仓产业园，资料面积 82,000m²、19 台货梯，均标明招商资料来源。宽 96、进深 54、柱距和设备坐标仍为示意配置，不能用该单栋模型推算园区资料总面积。道路、绿化及大门位置根据照片组织为可漫游场地，未进行测绘或 GIS 校准。出租率、租金、工单与设备状态均为演示；不是测绘、IFC 或工程验收模型。没有接入实时监控、消防状态、真实合同或工单。所有运营数字和记录在页面标注为演示数据。

模型参数及业务点位集中在 `frontend/src/views/twin/twinData.js`，建筑几何底稿实现位于 `warehouseModel.js`，场地与入口位于 `siteGeometry.js`。`warehouseAsset.js` 加载 GLB，`warehouseController.js` 用模型属性恢复选层、展开、室内和消防分组。`sceneWeather.js` 管理天气与照明，卸载时恢复共享场景和材质状态、释放自有资源。后续应以 CAD/IFC、楼层平面图或现场测量校准，再用真实建筑/房源/设备 ID 绑定后端。当前不向正式模块传递虚构数据库 ID。

源码中的 `/iot/camera`、`/iot/fire` 共用设备分类管理页 `DeviceCategory.vue`，尚不是实时视频播放器。物业、合同、园区和能耗入口映射到已有页面，当前点击只完成模块导航；点位级真实记录定位需要后续绑定。

## Blender 编辑与导出

本机 Blender：`D:/SteamLibrary/steamapps/common/Blender/blender.exe`。

- 可编辑源文件：`models/blender/dipark-warehouse.blend`（随源码版本管理）。
- Blender 实际渲染图：`artifacts/dipark-warehouse.png`。
- Blender 大门渲染图：`artifacts/dipark-warehouse-entrance.png`。
- 网页资产：`frontend/public/models/dipark-warehouse.glb`。
- 楼层分别放在 `01 Floor 1` 到 `07 Floor 7` 集合中；场地和屋顶分别位于 `00 Site`、`08 Roof`。楼层下有外壳、结构、室内、消防四个组。室内系统默认隐藏，编辑时可通过 Outliner 打开对应对象的可见性。
- 保留 `twinRole`、`floor`、`spaceKey` 自定义属性和父子关系。`spaceKey` 是模型本地索引，不是数据库 ID。当前网页按 7 层及不等层高参数解释几何；改变层数、层高、轴线或设备坐标时，需同步网页配置和点位。

编辑并保存 `.blend` 后，在仓库根目录运行以下命令即可更新网页资产，不会重新生成底稿或覆盖编辑：

```powershell
& 'D:/SteamLibrary/steamapps/common/Blender/blender.exe' --background models/blender/dipark-warehouse.blend --python scripts/blender/export_warehouse.py -- frontend/public/models/dipark-warehouse.glb
```

如需完全重建初始底稿，在 `frontend` 内运行 `node scripts/export-warehouse-seed.mjs`，再到仓库根目录运行 `prepare_warehouse.py`（见脚本头部命令）。重建会覆盖生成的 `.blend`，手工编辑版本请另存。导出器保留 [glTF 自定义属性](https://github.com/KhronosGroup/glTF-Blender-IO/blob/main/docs/blender_docs/scene_gltf2.rst)，包含隐藏的室内系统，并应用修改器。

经用户授权发布，实景对照所需的11张参考图随源码保存于 `frontend/public/twin-reference/reference-1.png` 至 `reference-8.png`，以及 `reference-9.jpg`（招商资料）、`reference-10.jpg`（建成实景）、`reference-11.jpg`（园区大门）。Vite 默认会将 public 内容复制到构建目录。`artifacts/` 下的构建日志、过程模型和本地渲染图，以及 Blender 备份文件 `*.blend1` 不纳入版本管理。

模型通过合并静态材质几何降低绘制次数，按楼层保留拾取信息。卸载释放 GPU 几何、材质、事件和动画循环；使用透视相机，窄屏自动增大视野角度，避免裁掉整个建筑。
