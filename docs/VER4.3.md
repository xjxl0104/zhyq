# ver4.3 发布说明：权威应收明细与自动售货机整合

## 发布范围

ver4.3 在 ver4.2 用户与角色权限管理之上新增两条业务能力：

1. 园区租金及物业管理费基础资料成为应收登记与计费的权威来源。
2. 在厂商未开放 API 的前提下，将自动售货机作为受控外部应用和本地经营数据模块接入智慧园区。

## 应收明细权威口径

系统按基础资料工作簿的 27 列原样承接租户、空间、面积、合同周期、递增、免租、优惠、租金、物业费、保证金、收款时间、收款账户和备注。导入时执行以下控制：

- 精确识别标题和 27 列表头，不接受静默列映射。
- 只读取公式缓存结果并保留原公式审计，不在服务器执行公式、宏或外部链接。
- 对业务行与总计行进行金额和面积核对。
- 预览阶段仅写共享导入批次和审计行；绑定租户及空间后才能确认。
- 完整收款账户使用 AES-GCM 加密，列表、预览和导出只显示掩码；查看完整值使用独立权限并记录审计。
- 合同审批只对已确认且已关联合同的应收登记表生成账单；租金、物业费、租金保证金和物业保证金分开入账。
- 账单使用稳定 `billing_key` 去重，重复执行不会重复生成。

## 自动售货机边界

厂商入口默认为 `https://fanmaiji.top/index?isFrom=login`。智慧园区只在用户点击后以 HTTPS 新窗口打开，并使用 `noopener,noreferrer`；不会附带园区 token。

当前明确不做：自动登录、验证码绕过、页面抓取、厂商密码或 Cookie 保存、向厂商系统反向写入。厂商未提供 API，因此页面会明确显示 `apiAvailable=false`；在获得真实厂商导出样例并通过回归测试前，`nativeFormatSupported=false`。

系统提供五类标准模板：

| 类型 | 稳定业务键 | 主要字段 |
|---|---|---|
| 机器 | 厂商机器编号 | 名称、点位、型号、运行状态、最后在线时间 |
| 销售 | 厂商订单号 + 行号 | 机器、商品、数量、原价、优惠、实付、支付时间、订单状态 |
| 补货 | 厂商补货单号 | 机器、商品、数量、补货人、补货时间 |
| 故障 | 厂商故障编号 | 机器、类型、发生/恢复时间、状态、描述 |
| 对账 | 厂商结算单号 | 周期、销售、退款、平台费用、净额、状态 |

所有类型都经过精确表头校验、逐行预览、文件哈希防重、业务键新增/更新、错误行说明原因后排除、确认入库和整批撤销。撤销只删除仍由该批次最后写入的本地副本，审计批次与排除记录保留。

## 经营数据中心

数据中心增加“经营收入来源”：

- 租金及物业应收：`fin_bill` 中收款方向、费用类型为“租金/物业费”的账单金额。
- 租金及物业实收：上述账单的实收金额。
- 售货机销售：受控导入的 `ops_vending_sale` 实付金额，排除“已退款”和“已取消”。

三项口径独立展示，不把售货机销售伪装成租金或物业账单。

## 权限

- 应收明细：`finance:receivable:*` 九项细分权限。
- 自动售货机：`vending:query`、`vending:import`、`vending:open`、`vending:config`。
- V32/V33 自动把新增权限授予现有 `admin` 角色；管理员升级后需重新登录刷新 JWT。

## 部署与回滚

上线前备份数据库与 `uploads`，配置固定的 `ZHYQ_FIELD_ENCRYPTION_KEY`，再让 Flyway 执行 V32/V33。迁移只新增表、字段、索引、应用卡片和权限，不删除现有业务数据。

应用代码可以回退，但数据库迁移不应手工删除或篡改。V32 已经加密保存的账户依赖原密钥；必须把该密钥纳入受控备份。售货机单个导入批次应优先通过页面“撤销该批次”回滚，不直接改表。
