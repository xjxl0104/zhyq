# P4 客户每单定价

2026-09-29 会议修改：P4 有定价权，P1–P4 的个人金额都按客户自定义；公司留存为总额减去所有个人分配。金额单位是元/单，支持 0.001 元。

## 小程序接口

所有接口要求 `ROLE_MP`；定价读写、人员管理还会在服务层检查当前伙伴为正常状态的 P4。后台管理员账号不等于 P4。

| 方法 | 路径（前缀 `/mp/v1/pricing`） | 内容 |
| --- | --- | --- |
| GET | `/customers` | 本人及邀请体系内归本人负责的客户，含是否配置 |
| GET | `/beneficiaries` | 本人邀请体系内正常、非内部的其他伙伴 |
| GET | `/customer/{customerId}` | 客户定价明细，仅负责该客户的 P4 可读 |
| PUT | `/customer/{customerId}` | 新增客户定价版本，返回定价明细 |
| GET | `/team` | 邀请体系内的其他正常伙伴，包含内部伙伴 |
| GET | `/positions` | P1–P4 的角色代码与当前名称，不含固定金额或比例 |
| PUT | `/team/{promoterId}/position` | 请求 `{ "code": "P2" }`，显式设置邀请体系成员角色并写审计 |

定价请求：

```json
{
  "totalPerOrder": 0.300,
  "ownerPerOrder": 0.023,
  "beneficiaries": [
    { "promoterId": 101, "amountPerOrder": 0.077 },
    { "promoterId": 102, "amountPerOrder": 0.001 }
  ]
}
```

`ownerPerOrder` 是 P4 本人金额，必须显式填写，可以是 0。其他受益人最多 2 人，不得重复、不得选择本人。`beneficiaries: []` 表示不分配给其他人。各金额非负且最多三位小数，个人合计不得超过总额。保留现有内部人员不计个人佣金规则：内部 P4 可以定价，但本人金额应为 0。

定价响应包含：`customerId`、`customerName`、`configured`、`canEdit`、`ownerPromoterId`、`ownerName`、`totalPerOrder`、`ownerPerOrder`、`allocatedPerOrder`、`companyPerOrder`、`remainingPerOrder`、`beneficiaries`、`updatedAt`、`pricingId`。

- `allocatedPerOrder`：其他受益人合计。
- `companyPerOrder` 与 `remainingPerOrder`：公司留存；上述示例为 0.199 元/单，不进入 P4 或其他个人钱包。
- `beneficiaries` 包含人员名称、角色与 `amountPerOrder` 快照。
- 未配置时 `configured=false`，金额、版本、时间为 null，受益人为 `[]`。不会返回默认金额。

## 管理端

`GET /crm/marketing/customer/{customerId}/pricing` 使用现有 `crm:marketing:customer:query` 权限，只读返回同一响应，`canEdit=false`。没有允许管理员代替 P4 改价的写入接口。

客户负责的 P4 根据客户推荐人的上级链查找最近的 P4。其他 P4 不得访问或修改该客户定价。授予下级 P4 后，该下级开始负责自己来源的客户；新负责人必须重新配置，旧定价不会自动转移。

P4 可以显式设置邀请体系内其他正常成员的 P1–P4 角色，不能修改本人。修改 P4 角色即授予定价权。服务在事务中按固定顺序锁定操作者和目标，再检查权限，角色变更经过原有岗位历史与审计服务。自动晋升/降级停用。旧 `/mp/v1/team/allocation` 比例修改接口拒绝写入，旧岗位固定比例、入仓评级比例不再允许编辑；角色名称等元数据仍可维护。

## 计佣与历史记录

- 园区签约的出库单使用 P4 客户配置，一条唯一出库单号计一单；包裹数、件数仍只用于合同服务费与云仓成本。
- `poolAmount` 是本单实际个人佣金合计；`commissionUnitPrice` 是含公司留存的总单价。公司留存单独记录 `companyPerOrder`。
- 新出库单未配置时明确失败并保留可重试路径，不回退旧评级/岗位比例，不写成已计佣订单。补齐配置后可重新导入或重试 ERP 事件。
- 配置采用追加版本；新生成的订单记录当前配置版本，已入账历史流水不重算。延迟导入但尚未入账的订单采用入账时配置。
- 订单快照：`pricingId`、`commissionUnitPrice`、`commissionOrderCount`、`companyPerOrder`，`baseMode=2`。
- 个人流水快照：`pricingId`、`amountPerOrder`、`orderCount`。退款扣回保留这些快照并抵扣原始金额。
- 合同服务收入、云仓成本和毛利校验继续生效。租赁月租、签约奖及云仓直签平台费保留原来的独立业务计算路径。

V74 新增不可变定价版本表，并将个人佣金、个人佣金池及结算批次金额扩展到三位小数。

V75 支持按分部分提现：原佣金 `amount` 不变，使用 `withdrawnAmount` 记录已成功提现/抵扣的累计金额，`withdrawalAmount` 记录当前申请锁定额；提现单 `commissionAllocations` 保存本次逐流水金额快照。100.001 元佣金可申请 100.00 元，打款后仍保留 0.001 元，日后可以和其他佣金一起累计。驳回只释放锁定，不增加已提现累计；退款按原始权益扣回，例如已经提现 100 元、剩余 0.001 元的原单退款后，净待抵扣金额为 100 元，不会重复扣款。

一笔原佣金同一时间只参与一张待处理提现单，未提部分在该申请打款或驳回后继续可用。现金申请保持两位小数；`/withdrawal/balance` 同时返回原始余额、向下截至两位小数的 `cashableBalance` 和不足分的 `fractionalBalance`。不四舍五入丢弃余额，不设定积分兑换规则。
