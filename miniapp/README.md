# 全民营销小程序：园区伙伴与云仓商家

uni-app + Vue3，同一工程输出微信小程序与 H5。当前正式小程序为“数智云仓全民营销助手”，AppID `wxc01f4ad2297319a0`。两个身份使用独立的业务权限与 token。

## 登录与注册

- 微信小程序默认提供**微信一键登录**和**手机号一键登录**，首次登录自动创建账号。微信一键登录不要求手机号；手机号一键登录使用微信授权号码。姓名、云仓名称等资料登录后补充，账号密码保留为备用入口；普通 H5 浏览器默认使用账号密码。
- 再次登录仍默认使用一键登录。设置或修改账号密码不会解除已有微信关联；原会话失效后，已关联微信的账号仍可通过微信或手机号一键登录，也可选用账号密码。仅通过账号密码注册且尚未关联微信的旧账号，需由运营核验关联，不能仅凭联系手机号自动合并。
- 账号和密码只需填写，不要求最低长度或字符组合，支持 `123 / 123`、中文及符号。账号沿用去除首尾空格、统一小写及同身份唯一规则，数据库存储容量为 512 个字符，超出时明确报错。密码完整参与 SHA-256 预哈希再 BCrypt 加盐散列，不设业务长度上限，不会在 72 字节处截断；已有 BCrypt 密码仍可登录和修改。
- 新伙伴注册必须填写有效的上级邀请码，邀请链接可自动带入；账号密码注册与首次微信一键登录均在服务端校验后绑定上级。已有伙伴登录无需重新提供邀请码，历史未绑定账号仍按原有期限补填。云仓注册不要求伙伴邀请码。
- 账号密码注册填写账号、密码并同意协议；伙伴另填上级邀请码，不要求确认密码、姓名、手机号或云仓名称。姓名与联系电话可登录后在“个人信息”补充，云仓商家还可补充云仓名称。
- 后补手机号仅用于联系，没有短信验证。微信一键创建的空资料账号可以在个人信息首次填写联系电话，之后如需改号联系运营；已有业务手机号不能据此认领/合并资料。已有微信用户登录后，在“我的 → 账号与密码”或云仓工作台“账号与密码”设置密码；已配置密码时修改须提供原密码。
- 伙伴注册写入 `crm_promoter`，显示于智慧园区“招商 → 全民营销 → 伙伴管理”。云仓注册写入 `crm_warehouse` 并进入资质审核，显示于“云仓管理/加盟申请”。凭据保存于 `crm_marketing_credential`，不创建管理后台 `sys_user`。
- 新云仓注册后直接进入工作台；“个人信息”用于保存基本联系资料，“加盟申请”用于正式办理资质与附件。保存个人信息不会提交加盟审核，注册账号也不代表审核通过。

## 临时测试入口

- 身份选择页和登录页提供“无需登录，进入测试体验”。入口进入独立的前端演示页，使用预置数据浏览园区伙伴与云仓商家工作台，不读取或写入任何业务接口，也不会创建 token。
- 演示页中的推荐客户、删除、提现、ERP 凭证、结算和资料提交等按钮只展示“登录后可用”提示；模拟推荐只保存在当前页面内，退出后自动清空。它不替代微信 mock 登录，也不应改造成匿名业务接口。

## 客户定价、称号与提现

- 只有正常状态的 P4 可以给自己负责的客户／品牌定价。P1–P4 的每单金额均无固定默认值：P4 显式填写总佣金、本人金额，以及最多 2 位具体受益人的金额；也可不分配。单位为元／单，支持 0.001 元精度，各方金额合计不得超过总佣金，公司保留剩余金额。
- P4 在“我的团队”设置邀请体系成员的 P1–P4 称号；称号不自动决定金额，也不按业绩自动晋升。将成员设为 P4 会授予其负责客户的定价权，负责 P4 变化后的客户须重新配置定价。
- 佣金余额保留 3 位小数，现金提现精确到分。“全部可提现金额”按分向下截取，例如余额 100.009 元可申请 100.00 元，余下 0.009 元继续保留；仍须满足最低提现金额和收款资料审核要求。支持部分金额提现，代扣和实际到账以财务审核为准。
- 积分与礼品兑换规则尚未配置，页面继续按金额展示收益，不预设积分兑换比例。既有历史记录保留原计佣规则，新配置用于之后产生的计佣记录。

## 体验受限驳回后重新提审

减少注册字段只能降低进入门槛，不能代替审核所需的完整体验条件。按实际驳回通知，在提审页面提供可用的体验账号及密码，或完整功能截图、录屏；建议伙伴和云仓各提供一个独立测试账号，并写明“选择身份 → 账号密码登录”的路径。

需要查看订单、合同、结算等业务流程时，测试账号应由运营配置合适的权限和隔离测试数据。不要用管理员账号、真实客户数据或审核专属的权限绕过来提供体验。微信审核、发布与服务端部署是两步：后端上线后，需上传这次构建的小程序包再重新提交审核。

## 微信好友分享

- 所有页面均支持右上角「发送给朋友」。普通页面使用共用 `appShareMixin`，分享后进入身份选择入口，按接收方自己的登录状态进入工作台；卡片只包含固定品牌封面，不携带当前客户、订单、金额或账号参数。
- 「邀请伙伴」页保留独立分享回调与邀请码路径，使用相同的固定封面。新增页面时需接入 `appShareMixin`；构建检查会验证所有页面的原生分享入口。
- 本次补充的是微信好友与群聊分享。朋友圈不在本次修复范围。

## 本地运行与构建

```sh
pnpm install
pnpm dev:h5
pnpm dev:mp-weixin
pnpm build:h5
pnpm build:mp-weixin
```

H5 开发请求经 Vite 代理到本机 `8090`。微信构建默认接口为 `https://zhyq.aoleplat.com/api/mp/v1` 和 `/api/wh/v1`，可用 `VITE_API_BASE`、`VITE_WH_API_BASE` 覆盖；微信端必须为 HTTPS 绝对地址。构建结束自动核对产物与源码的 AppID。

微信开发者工具导入 `dist/build/mp-weixin`。确认工具实际显示的 AppID 与源码一致，再重新编译/真机预览。不要只修改生成目录的 `project.config.json`；后续构建会覆盖它。

## 微信真实登录配置

前后端默认关闭 mock。正式服务器配置必须成对匹配：

- `WX_MP_APPID=wxc01f4ad2297319a0` / `WX_MP_SECRET`
- `WX_WH_APPID=wxc01f4ad2297319a0` / `WX_WH_SECRET`
- `WX_MP_MOCK_LOGIN=false` / `WX_WH_MOCK_LOGIN=false`

本工程同一个小程序包含两个身份，服务器两组凭据应配置为当前正式小程序的同一组 AppID/Secret。旧版小程序已停用，不得继续使用旧版的 AppID 或 Secret，也不得将其他小程序的 Secret 与当前 AppID 混用。密钥仅放服务器环境变量，不写前端或 Git。

一键登录流程：用户勾选协议后，`uni.login` 获取一次性 code，连同运行中的 AppID 和 `agreed=true` 发送 `/auth/quick-login`。服务端验证微信身份，老用户进入原工作台，新伙伴须提供有效邀请码后才创建档案并绑定上级。手机号按钮先取得微信 `getPhoneNumber` 的动态 `phoneCode`，再获取登录 code，并一次提交同一接口；服务端先解析号码、匹配安全的现有身份，再决定是否创建。用户拒绝手机号授权时仍可改用不要求手机号的微信一键登录。每次重试重新获取登录 code，不信任前端提供的 openid 或生产环境明文手机号。

旧版 `/auth/wx-login`（返回 5 分钟一次性 `loginTicket`）和 `/auth/bind-phone` 保持兼容。旧 `encryptedData/iv` 绑定仍须票据，一键手机号按钮使用现代 `phoneCode`。已有账号密码档案仍需使用原账号，不能凭手机号码自动合并身份。

切换 AppID 会改变用户 openid。旧测试号档案不会自动合并或清空；须由原登录会话先设置密码，或由运营核验后迁移微信绑定。

## 开发模拟

仅开发时显式设置前端 `VITE_MP_MOCK_LOGIN=true` / `VITE_WH_MOCK_LOGIN=true`，以及对应后端 `WX_MP_MOCK_LOGIN=true` / `WX_WH_MOCK_LOGIN=true`。测试标识模拟微信身份、手机号明文填写；不可用于生产。

## 上线验证

- 由 Flyway 按序执行当前版本的全部迁移，包括凭据、客户定价及佣金 3 位小数的迁移；上线前核对数据库迁移版本，不能只执行旧版 V66。
- 反代部署配置 `ZHYQ_AUTH_TRUSTED_PROXIES` 为实际可信代理的 IP/CIDR。服务端仅从可信 socket peer 接受 X-Forwarded-For，并从右向左剥离可信跳点；禁止配置为全网。代理 IP 变化须同步后端配置，防止所有用户共用代理 IP 限额。
- 检查两端注册落库、错误密码、重复手机号、已有用户设置密码及跨角色接口拒绝。
- 在微信公众平台为正式小程序配置 request 合法域名 `https://zhyq.aoleplat.com`，确认手机号能力可用；真机微信授权需由微信用户亲自确认。
